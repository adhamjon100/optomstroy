# tools/pg — заметки о решениях

Дата: 2026-10-21. Этап B («контракты»). Раннер нужен задачам RM-B-005, RM-B-008 и RM-C-006 (13_IMPLEMENTATION_ROADMAP §3.2–§3.3).

1. **Версия.** Взят `embedded-postgres@17.10.0-beta.17` — последняя версия ветки 17.x в npm на 2026-10-21; тег `latest` указывает на `18.4.0-beta.17`. Основания: D-03 и 07 §2.1 фиксируют PostgreSQL 17, а вопрос «17 или 18» (Q-104/Q-145) открыт с рекомендацией 17. Суффикс `-beta.N` — схема версий пакета (версия PostgreSQL + сборка обёртки), сервер внутри — релизный PostgreSQL 17.10. Версии `embedded-postgres` и `pg` (8.23.1) закреплены точно.
2. **Аналог psql.** Клиентов `psql` и `pg_dump` в бинарном пакете нет, а Docker отсутствует (ядро R0 §0). Поэтому команды выполняются через `node-postgres`, по одной, в режиме autocommit, а деление на команды повторяет `psqlscan.l`. Поведение `ON_ERROR_STOP=1` воспроизведено так: первая ошибка → код 1, затем текст ошибки с `файл:строка:колонка`. Номер строки вычисляется из `position` ошибки, если сервер его вернул; иначе берётся строка начала команды.
3. **Расширения.** По умолчанию раннер их **не** создаёт. Если миграция пишет `CREATE EXTENSION pg_trgm` без `IF NOT EXISTS`, заранее созданное расширение сломало бы её. Опция `--ext` создаёт их явно. Раннер всегда печатает доступность `pg_trgm`/`unaccent`/`pgcrypto` (в 17.10: 1.6 / 1.1 / 1.3).
4. **Локаль.** На Windows используется `en-US` (libc), на Linux и macOS — `en_US.utf8` или `C.UTF-8`. Проверено фактически: при `lc_ctype=C` `show_trgm('Смеситель')` возвращает `{}`, а `lower('СМЕСИТЕЛЬ')` не меняет регистр, то есть поиск по кириллице (07, индексы pg_trgm) при такой локали проверить нельзя. С `en-US`: 10 триграмм, `lower` → `смеситель`, `similarity` = 0.5. Образ `postgres:17` по умолчанию тоже использует не-C локаль `en_US.utf8`. Провайдер `builtin C.UTF-8` отклонён: он оставляет `lc_ctype=C`.
5. **Параметры сервера.** `timezone=UTC` — как у образа `postgres:17` по умолчанию; бизнес-часовой пояс Asia/Bishkek задаётся приложением. `--data-checksums` — как `POSTGRES_INITDB_ARGS` в примере compose 16 §4.4. `fsync`, `synchronous_commit` и `full_page_writes` отключены: кластер одноразовый. Сервер слушает только `127.0.0.1`. Аутентификация — `scram-sha-256` со случайным паролем на запуск; пароль не печатается, при `--keep` пишется в `<каталог>/run-sql.conn`.
6. **Имя БД.** Используется `pos_test`, как в задании. Владелец — суперпользователь `postgres`. Роли мигратора и приложения (R0 §17.7, `DB_MIGRATOR_PASSWORD_FILE`) раннер не создаёт: это зона RM-C-006.
7. **`--repeat`.** В задании сказано «ожидается ошибка или 0 изменений — просто выводи результат», поэтому `--repeat` всегда печатает итог и не влияет на код выхода. Для приёмки RM-C-006 п. 4 («повторный запуск идемпотентен, 0 изменений») добавлен `--repeat-strict` с кодом 1 при ошибке или изменениях. «Изменения» — это разница отпечатков схемы и данных (README, «Отпечаток»), а не только `rowCount` DML: так ловятся и `CREATE OR REPLACE` с другим телом, и `ALTER`. Значения последовательностей в отпечаток не входят. Если повтор упал внутри открытой файлом транзакции, раннер делает `ROLLBACK`, чтобы снять отпечаток и выполнить check.
8. **Порядок.** Порядок такой: применение → повтор → check. Check видит итоговое состояние после повтора.
9. **Коды выхода.** 0 — успех, 1 — ошибка SQL (как у `psql` с `ON_ERROR_STOP` на ошибке скрипта — код 3; здесь по заданию 1), 2 — инфраструктура или использование.
10. **Отличие формы команды от приёмки.** В RM-B-005 и RM-B-008 приёмка записана как `psql -v ON_ERROR_STOP=1 -f …` «на локальном PostgreSQL 17 или в одноразовом CI-сервисе `postgres:17`». Этот раннер — локальный PostgreSQL 17 с эквивалентной семантикой остановки на первой ошибке. В логах для RM-B-013 указывать фактическую команду `node tools/pg/run-sql.mjs …` и строку `version()` из вывода.
11. **`--set` (B-AR-09, 2026-10-21).** Миграция `0001_init.sql` создаёт `dev_outbox` только при `app.env IN ('dev','test')` (отказ закрыт). Раннер передаёт параметр через `SELECT set_config(name, value, false)` сразу после подключения — это эквивалент `PGOPTIONS='-c app.env=test'` у `psql`, действует на все файлы, повтор (`--repeat`) и check-файлы одного соединения. Имена ограничены видом `prefix.name` (пользовательские параметры), чтобы опция не меняла серверные настройки.
