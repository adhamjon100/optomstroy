Краткое содержание

  • Документ резервирует структуру и элементы экранов авторизации и регистрации SCR-00…SCR-08 и глобальных состояний SCR-90 (ядро R0 §9) в трёх раскладках D-18: compact 360×760, medium 800×1100, expanded 1366×820.
  • Для каждого экрана: назначение, три раскладки с выносками, таблица элементов (компонент R0 §8.5, поведение, зарезервированный UI-<SCR>-NNN), мини-кадры состояний (загрузка / успех / ошибка / нет сети / блокировка).
  • Единственный способ входа — телефон +996 + OTP (D-09, D-10); «сканирование лица» промта заменено системной биометрией + PIN с отдельным согласием (D-13, D-14); SCR-05 специфицирован как условный модуль R2 (Q-003), SCR-06 — только для режима клиента (Q-001).
  • Персонаж Mascot (D-40) — 6 состояний, визуальный слой независим от результата проверки; приложение A описывает кадры и тайминги.
  • Палитра — токены ядра R0 §8.1 (вариант A+ по умолчанию); вариант B «Оранжевый» (Q-006) включается переключателем на чистом CSS; имена вне ядра помечены НОВОЕ ИМЯ.
  • Проектные значения, отсутствующие в ядре (таймауты, интервалы опроса, сроки блокировок), помечены [ТИПОВО: требует проверки] и собраны в разделе «Открытые вопросы»; трассировка экранов на SRC-… — в предпоследнем разделе; поэлементную трассировку ведёт 02_SCREEN_SPECIFICATION.
  • Приложения: B — схема переходов между экранами (inline-SVG), C — сводный реестр UI-ID; в конце — замечания к ядру для оркестратора и «Журнал сверки с ядром» (v1.4).
  • Ревизия 1.4 (ядро v1.4, §19.3): RegistrationStepper — 3 шага «Данные · Защита входа · Готово» (+ «Привязка» при SCR-06); информирование об обработке ПДн и отметка «Я ознакомлен(а)» перенесены на SCR-03 (UI-03-014), UI-04-011 зарезервирован и не используется; телефон пользователя на устройстве не хранится — SCR-08 его не показывает и не предзаполняет; кнопка биометрии в step-up в R1 скрыта (R2); блокировка при возврате из фона — 5 мин, idle — 30 мин.
Правила чтения. Для каждого экрана даны три раскладки: compact (телефон 360×760 lp, показан в масштабе 0,9), medium (планшет 800×1100 lp, масштаб 0,6), expanded (POS/десктоп 1366×820 lp, масштаб 0,6) — брейкпоинты D-18. Если раскладка совпадает с другой, вместо схемы стоит пометка «как medium» / «как compact». Чёрные кружки с номерами — выноски элементов; под каждым экраном — таблица элементов с компонентом из R0 §8.5 и зарезервированным идентификатором UI-<SCR>-NNN (номера назначаются по таблице элементов и едины для всех раскладок экрана; порядок номеров — строго сверху вниз, слева направо по раскладке compact; на medium/expanded позиция элемента может отличаться, номер при этом не меняется; строки «—» — состояния без выноски в базовой раскладке; элементы, добавленные при ревизии внизу compact или существующие только на medium/expanded (например, логотип в бренд-панели), получают номера после последнего зарезервированного номера экрана — последовательность на compact остаётся возрастающей; владелец идентификаторов — 02_SCREEN_SPECIFICATION, здесь они резервируются; в ревизии 1.2 номера SCR-03, SCR-04, SCR-05 и SCR-08 перенумерованы по порядку compact — 02 их ещё не использовал; после передачи в 02 перенумерация запрещена). SCR-08 Быстрый вход (биометрия / PIN) · /auth/unlock · авторизованные · R1

Назначение. Разблокировка сохранённой сессии без SMS. Экран работает в двух режимах (R0 §17.2): полноэкранный — при холодном старте с сохранённой сессией staff (всегда, из SCR-00: PIN обязателен для всех staff, D-48); overlay — при idle-блокировке 30 мин (D-12, SESSION_IDLE_LOCK_MINUTES), при возврате из фона > 5 мин (AUTH_BACKGROUND_LOCK_MINUTES) [РЕШЕНИЕ: ядро §19.3] или по 401 UNLOCK_REQUIRED (ядро §18.2 п.5) поверх текущего рабочего экрана с сохранением его состояния (маршрут, корзина, введённые поля, прокрутка); после разблокировки overlay снимается и работа продолжается с того же места (мини-кадр 7, UI-08-015). Основные раскладки ниже — полноэкранный режим. Биометрия — системный prompt с криптопривязкой (Android Keystore / iOS Keychain), вызывается автоматически при открытии экрана; разблокировка — POST /auth/unlock {method: biometric} [РЕШЕНИЕ: ядро §19.3, §18.2 п.5]; PIN приложения — запасной способ и основной на Windows (D-13). Проверка PIN — только на сервере (D-48: app_pins, Argon2id + PIN_PEPPER_FILE; POST /auth/unlock {method: pin} — refresh + PIN, публичный путь без Bearer (ядро §18.2 п.5) → новый access), поэтому разблокировка требует сети; офлайн-разблокировка — вне R1 (D-48, Q-241). Неверный PIN — 401 PIN_INVALID {attemptsLeft}; после 5 неверных PIN подряд — 423 PIN_LOCKED {until} (оба кода канонические — R0 §17.4; число попыток — [ТРЕБУЕТ РЕШЕНИЯ ЗАКАЗЧИКА: Q-004]) и вход только по SMS (SCR-01); отзыв сессии устройства при блокировке — [ТИПОВО: требует проверки]. «Забыли PIN?» — по 02 §9 ч. Номер телефона и его маска на SCR-08 не показываются и никуда не предзаполняются [РЕШЕНИЕ: ядро §19.3]. Персонаж — малый плейсхолдер (09 §11.1): idle при открытии, typing при вводе PIN, verifying на /auth/unlock, success / error — только по ответу сервера.

Единственный брендовый акцент на персонаже — деталь одежды/аксессуар brandAccent #FF8700 (на схеме — пунктирная линия). Визуальный слой независим от результата проверки: success/error включаются только по ответу сервера.

idle
Экран открыт. Дыхание scale 1→1.015 (2 с), моргание 3–5 с
typing
Фокус в поле; зрачки следуют курсору ±6 lp; кивок на цифру (200 мс)
verifying
Запрос отправлен; «думает», 3 точки, loop 1,2 с; таймаут 15 с → error
success
2xx: улыбка 200 мс → галочка scale-in 250 мс → переход через 400 мс (≤ 900 мс всего)
error
Ошибка: покачивание 2×±4°, брови вниз (400 мс); поле — shake; через 1,5 с → retry
retry
Пользователь начал ввод заново; возврат в idle 300 мс

Reduce-motion (оба флага Flutter + переключатель в SCR-42; вход Rive reduceMotion, R0 §17.5): статичные кадры состояний или crossfade ≤ 80 мс, без shake, только цвет и текст. Персонаж скрывается при высоте окна < 640 lp с открытой клавиатурой; размеры 150 (compact) / 180 (medium) / 240 (expanded) lp.

Приложение B. Переходы между экранами авторизации

Пунктир от главного экрана к SCR-08 — overlay-режим при idle-блокировке 30 мин и при возврате из фона > 5 мин (R0 §17.2, ядро §19.3); петля на SCR-08 — «Забыли PIN?»: вход по SMS через SCR-01/02 (номер вводится заново — телефон на устройстве не хранится, ядро §19.3) и экран «Новый PIN» (UI-08-014), корзина сохраняется. Регистрация SCR-03 → SCR-04 → «Готово» (UI-04-015) — три шага индикатора (ядро §19.3). SCR-90 (нет сети, step-up) накладываются на любой экран; SCR-05 присутствует только при включённом модуле FACE-SCAN (Q-003); SCR-06 — только в режиме клиента (Q-001).
