## Краткое содержание

- Четыре класса окна по R0 §8.3 / D-18: **compact < 600 lp** (телефон), **medium 600–1023** (планшет), **expanded 1024–1599** (POS-терминал, десктоп, макеты 1280–1536 px), **large ≥ 1600** (широкие мониторы; контент ограничен).
- Для **каждого** экрана `SCR-00…SCR-50` приведена таблица из девяти строк: раскладка, навигация, положение корзины, число колонок, сайдбар/боковые панели, модальность, ориентация, клавиатура (аппаратная на Windows, HID-сканер, экранная), тач-цели и плотность. `SCR-90` (overlay/dialog) описан строками по видам глобальных состояний; атрибуты «Колонки», «Сайдбар/панели», «Модальность», «Ориентация» у него наследуются от экрана под overlay (примечание под таблицей SCR-90).
- Общие правила (§1): ширина окна определяется `MediaQuery.sizeOf`, раскладка контейнеров — `LayoutBuilder`; ориентация не блокируется; телефон в ландшафте — двухпанельная раскладка; два режима плотности — токен `DsDensity {standard, compact}` (R0 §17.5; значения — R4 §5.6); тач-цели ≥ 48 lp на Android и сенсорных Windows-POS (44 pt — только iOS; 44 — цель кнопки S по R0 §8.3); сканер HID — на всех платформах, камера — только Android/iOS.
- Правила масштабирования шрифта (§9): поддержка системного масштаба до **1,3×** без потери функций (NFR-A11Y-001), ограничение `textScaler` ≤ 1,3 на POS-экранах, правила переноса и сокращения колонок при увеличении.
- Ядро v1.2 (R0 §17) внесено **прямо в таблицы §1–§10** (§15 — подробные таблицы режимов SCR-08, размещение компонентов и журнал): два режима SCR-08 (полноэкранный при холодном старте / overlay при idle-блокировке) по классам окна, размещение компонентов R0 §17.5 (`CartFab`, `CategoryTile`, `ImageGallery`, `WarehouseStockTable`, `OptionTile`, `RegistrationStepper`, `DocumentPreview`, `AppTooltip`), состав SCR-43 по ролям, новые варианты SCR-90, `DsDensity`, `r-xl 20`, формат телефона.
- Число колонок сетки каталога вычисляется по ширине контейнера по формуле 03 §7.3 (минимальная карточка 160 lp), а не по ширине окна (§1.3). Фиксированные размеры диалогов и листов — проектные `[ТИПОВО]`; окончательные значения задают 03 и 02.
- Ядро v1.8 (R0 §23) внесено прямо в таблицы (журнал — §16, строки v1.8): блок «Ожидают оплаты» SCR-30; SCR-38 — две плитки способа, смена способа без step-up; SCR-39 — «Согласовать»/«Отклонить»; SCR-45 — «Выдать аварийный код входа».
- Ядро v1.4 (R0 §19) внесено прямо в таблицы (журнал — §16): горячие клавиши Windows-POS **F9 — «Создать заказ», F8 — «Отложить заказ»** (03 A11Y-009, Q-111); SCR-34 — step-up только для детализации документов, сводка долга видна без него; блокировка при возврате из фона — **5 мин**, idle — 30 мин; `AppBottomSheet` вариант `side` — **400 (medium) / 480 (expanded, large)**; `StepUpDialog` на compact — нижний лист, без кнопки биометрии; размер текста — системный масштаб, настройка в приложении — Q-218(а) (FS-14); элементы R2 по R0 §19.2/§19.4 помечены «R2».
- Все значения — проектные, статус `[РЕШЕНИЕ: D-18]` либо `[ТИПОВО]`; размеры устройств заказчика — `Q-008`, сенсорность POS-мониторов — `Q-008`, сканеры — `Q-009`.

## 1. Общие правила адаптивности

### 1.1. Классы окна и базовая раскладка (R0 §8.3, D-18, R4 §5.2)

| Класс | Ширина окна, lp | Устройство (типично) | Оболочка (навигация) | Контент | Корзина | Плотность по умолчанию |
|---|---|---|---|---|---|---|
| compact | < 600 | телефон (портрет), узкое окно Windows | `BottomNavBar` 5 пунктов, высота 64 (80 с safe area) | 1 колонка; поля 16; категории — горизонтальные `CategoryChip` под `SearchBar` (категория с подкатегориями — `CategoryTile`) | панель-итог `CartFab` (сумма + счётчик, R0 §17.5) закреплена снизу над `BottomNavBar`, высота 56 → экран `/cart` или `AppBottomSheet` | standard |
| medium | 600–1023 | планшет (портрет/ландшафт), телефон в ландшафте ≥ 600 | `NavigationRailApp` 72 (с подписями: 96) слева | 2 панели: rail + контент; поля 24; категории — сворачиваемая колонка 240 или drawer | `CartPanel` как overlay в `AppBottomSheet` вариант `side` 400 справа (R0 §19.4) по кнопке/`F4`, либо панель-итог | standard |
| expanded | 1024–1599 | POS-терминал Windows, десктоп, планшет 12" ландшафт; макеты 1280–1536 | сайдбар 240–292 (категории + разделы), `TopAppBarPos` с поиском, часами, профилем, колокольчиком `[ПОДТВЕРЖДЕНО: макет]` | 3 колонки: сайдбар / контент / корзина; поля 24–32 | **постоянная** `CartPanel` 320–340 справа `[ПОДТВЕРЖДЕНО: макет]` | compact (строки 48, карточки padding 12, кнопки 40 визуально / 48 цель — POS-мониторы считаются сенсорными до ответа Q-008) |
| large | ≥ 1600 | широкий монитор | как expanded | контент ограничен `max 1200` по центру; 5–6 карточек в ряд по §1.3; поля растут | постоянная `CartPanel` 340 | compact |

Правила:

- R-1. Класс определяется по ширине **окна** (`MediaQuery.sizeOf(context).width`), а не устройства: окно Windows можно сузить до compact — раскладка переключается без перезапуска и без потери состояния (`IndexedStack` веток) `[ПОДТВЕРЖДЕНО: docs.flutter.dev — R4 §2.3]`.
- R-2. Внутри экрана ширина отдельного контейнера (например, контент-колонки при открытой корзине) измеряется `LayoutBuilder`; число колонок сетки — по ширине контейнера, а не окна (§1.3).
- R-3. Ориентация не блокируется ни на одной платформе (R4 §5.2). Телефон в ландшафте шириной ≥ 600 lp переходит в medium (rail + контент).
- R-4. Пороги 600/1024/1600 — токены `ds.breakpoint.compact|medium|expanded|large`; имя `ds.breakpoint.large ≥ 1600` — **каноническое** (R0 §17.5), имена `compact|medium|expanded` — `[НОВОЕ ИМЯ]` (R0 §8.3 задаёт для них пороги без имён токенов; предложение для DS); порог 1024 для трёхколоночного POS-режима — проектный `[ТИПОВО]`, Material-порог 840 не используется как отдельный класс.
- R-5. Safe areas (вырезы, жесты, строка состояния) учитываются на compact/medium; на Windows — заголовок окна системный, `TopAppBarPos` под ним.
- R-6. Переход между классами при изменении размера окна — без анимации (мгновенная перестройка), чтобы не «прыгать» при ресайзе `[ТИПОВО]`.

### 1.2. Плотность (R4 §5.6)

| Токен `DsDensity` (R0 §17.5) | Строка списка | Карточка (padding) | Кнопка M | Иконка | Где по умолчанию |
|---|---|---|---|---|---|
| standard | 56 (72 с миниатюрой) | 16 | 44 | 24 | compact, medium |
| compact | 48 | 12 | 40 визуально / 48 цель (невидимый padding; 44 pt на iOS) | 24 (20 в плотных строках) | expanded, large |

Ручной выбор плотности — SCR-42 «Плотность интерфейса» (`DsDensity.standard` / `DsDensity.compact` / авто — по классу окна по таблице выше). Плотность `compact` уменьшает только **видимые** размеры; минимальная тач-цель 48 lp (R0 §8.3, D-18, NFR-A11Y-001) не уменьшается ни в одном режиме. Значение R4 §5.6 «40 / 44 цель» заменено на «40 / 48 цель» — см. «Замечания к ядру» §13 п. 4.

### 1.3. Число колонок сетки каталога по ширине контейнера

Число колонок считается по ширине **контейнера** (R-2), а не окна — формулой `03_UX_UI_DESIGN_SYSTEM.md` §7.3 (приоритет 03 над `visual/`, README §3): `колонок = max(2, min(6, floor((W + gap) / (160 + gap))))`, где W — ширина контентной зоны без боковых полей (окно − rail/сайдбар − корзина − 2 × поле), gap — 12 (`DsDensity.compact`, expanded/large) или 16 (`standard`, compact/medium). Ширина карточки = (W − gap × (n − 1)) / n.

| Окно, lp (класс) | Расчёт W (без полей) | Колонок | Карточка, lp | Примечание |
|---|---|---|---|---|
| 360 (compact) | 360 − 2×16 = 328 | 2 | 156 | на compact минимум 2 колонки (исключение из минимума 160); вид по умолчанию — `ProductCardList`; < 360 — только список |
| 412 (compact) | 412 − 32 = 380 | 2 | 182 | |
| 600 П (medium) | 600 − 72 (rail) − 48 = 480 | 2 | 232 | планшет портрет |
| 800 П (medium) | 800 − 72 − 48 = 680 | 3 | 216 | |
| 1000 Л (medium, колонка категорий 240) | 1000 − 72 − 240 − 48 = 640 | 3 | 203 | при свёрнутой колонке категорий W = 880 → 5 колонок по 163 |
| 1024–1111 (expanded) | 1024 − 240 (SB) − 320 (CP) − 48 = 416 … 503 | 2 | 202–245 | 3 колонки — при SB, свёрнутом до 72 (W = 584…671 → 187–216); или режим «Список»/«Компакт» |
| 1112–1355 (expanded) | ≈ 504 … 675 (SB 240–292 + CP 320–340) | 3 | ≈ 160–217 | 1280 lp: W = 1280 − 292 − 340 − 48 = 600 → 3 × 192 |
| 1356–1527 (expanded) | ≈ 676 … 847 | 4 | ≈ 160–203 | 1440 lp: W = 760 → 4 × 181 |
| 1528–1599 (expanded) | ≈ 848 … 919 | 5 | ≈ 160–174 | 1536 lp: W = 856 → 5 × 162 — **5 в ряд, как на макете** `[ПОДТВЕРЖДЕНО: макет]` |
| 1600–1715 (large) | 1600 − 632 − 2×32 = 904 … 1019 | 5 | ≈ 171–194 | |
| ≥ 1716 (large) | ≥ 1020, ограничение 1200 | 6 | ≈ 160–190 | контент ≤ 1200 по центру |

Минимальная ширина карточки — **160 lp** (03 §7.3; название в 2 строки 14/20, цена 18/700, кнопка M на всю ширину); прежнее значение этого документа 150 lp и таблица «по ширине окна» (3–4 колонки при 1024–1279, 5 при 1280–1599) заменены — при сайдбаре и постоянной корзине они давали карточки ≈ 125–135 lp. Отступ между карточками 12 (compact-плотность) / 16. Строки «Колонки» таблиц экранов §4–§8 ссылаются на эту таблицу.

Все фиксированные размеры диалогов, листов и модальных окон в §1.4 и в таблицах экранов §3–§8 (480, 560, 640, 720, 640×720, 720×680, 1000 и т. п.) — проектные значения `[ТИПОВО]`; окончательные размеры задают 03 (§8 раскладки) и 02 (карточки экранов). Подтверждённой макетом считается только **компоновка** (число колонок, порядок блоков), но не размер в пикселях.

Ширина side sheet (сокращение **SS** в таблицах §3–§8) — **каноническая** `[РЕШЕНИЕ: ядро §19.4]`: `AppBottomSheet` вариант `side` — **400 lp на medium, 480 lp на expanded и large**; во всех таблицах экранов «SS 400» относится к medium, «SS 480» — к expanded/large. Не являются side sheet и сохраняют свои ширины: постоянная `CartPanel` 320–340 на expanded/large, встроенная `FilterPanel` 280–320 внутри контент-колонки, popover (280–400).

## 2. Как читать таблицы экранов

Каждый экран описан таблицей «атрибут × класс окна». ## 9. Правила масштабирования шрифта

Источник: D-17 (шкала 12…32, минимум 12 lp, `tabularFigures`), R4 §4.2 (поддержка до 1,3×, ограничение `textScaleFactor` ≤ 1,3 на POS), NFR-A11Y-001, R4 A11Y-005/A11Y-008.

| № | Правило | Детали |
|---|---|---|
| FS-1 | Системный масштаб текста поддерживается в диапазоне **0,85×…1,3×** без потери функций | `MediaQuery.textScalerOf`; значения > 1,3 ограничиваются до 1,3 (`TextScaler.clamp`) на всех классах; < 0,85 — до 0,85 (чтобы не нарушить минимум 12 lp) `[ТИПОВО]` |
| FS-2 | Минимальный размер текста после масштабирования — 12 lp для слов; `micro 11` — только 1–2 цифры в бейджах (A11Y-008) и **не** масштабируется ниже 11 | бейджи `NotificationBell`, корзины растут до 1,3× вместе с текстом (диаметр 18 → 22) |
| FS-3 | Цены, остатки, коды — `tabularFigures`, при масштабе 1,3× колонки таблиц расширяются, а не обрезают число; при нехватке ширины таблица переходит в горизонтальную прокрутку с закреплённой первой колонкой | `PriceText`, `CartSummary`, таблица остатков по складам в SCR-14 (`WarehouseStockTable`, R0 §17.5) |
| FS-4 | Высоты строк и кнопок растут **вместе с текстом** (не фиксированы): строка 48 → до 56; кнопка M 44 → до 52; `BottomNavBar` 64 → 72 | предотвращает обрезку; верстка через `minHeight`, не `height` |
| FS-5 | Сетка каталога при масштабе ≥ 1,15× уменьшает число колонок на 1 (минимальная ширина карточки в формуле §1.3 пересчитывается: 160 × scale), при ≥ 1,3× на compact — принудительно `ProductCardList` | §1.3 |
| FS-6 | `BottomNavBar` при масштабе ≥ 1,2× показывает подпись только у активного пункта; `NavigationRailApp` переходит в режим «только иконки» с тултипами | — |

| FS-8 | Модальные окна/диалоги при 1,3× на expanded переходят от фиксированных размеров к `maxWidth`/`maxHeight` 90 % окна с внутренней прокруткой; `CheckoutStepper` horizontal переходит в compact-вариант «Шаг 2 из 4» при нехватке ширины | SCR-21, SCR-38 |
| FS-9 | `OtpField`/`PinField` при 1,3× — ячейки 56×64 (6 ячеек = 376 lp; на compact < 400 — интервал 6) | SCR-02/04/08 |
| FS-10 | Заголовки `display 32` / `h1 28` на compact при 1,3× ограничиваются 36 lp визуально (`clamp` для уровней display/h1), остальные уровни масштабируются линейно | предотвращает перенос заголовка на 3 строки |
| FS-11 | Текст в `StatusChip`/`ReceivableBadge`/`CategoryChip` не обрезается: чип растёт по ширине, ряд чипов переносится (compact) или прокручивается (expanded) | — |
| FS-12 | Жирность не меняется при масштабе; контраст (A11Y-001) не зависит от масштаба; при 1,3× пороги «крупного текста» (≥ 24 px / ≥ 19 px bold) достигаются раньше, но требования AA 4,5:1 для body сохраняются | R4 §3.4 |
| FS-13 | Тестовые проверки: golden-тесты `alchemist` на 1,0× и 1,3× для SCR-10, SCR-14, SCR-20, SCR-21, SCR-30 на compact/expanded (12_TEST_PLAN) | D-04 |

## 13. Замечания к ядру

1. D-18 задаёт для medium «корзина overlay 320»; для планшета в ландшафте ≥ 900 lp здесь допущена постоянная панель 300 `[ТИПОВО]` — просьба подтвердить или оставить только overlay.
2. На экранах, не связанных с продажей (SCR-24, SCR-30…37, SCR-41…48), постоянная корзина на expanded **скрывается**, а правая колонка используется под действия экрана; D-18 это не оговаривает — предлагается зафиксировать правило «CP постоянна только в ветках Каталог/Избранное/Корзина».

### 15.5. Общие правила, уточнённые ядром v1.2

- **Плотность** — токен `DsDensity {standard, compact}` (R0 §17.5); таблица §1.2 и столбцы «ТЦ/плотность» читаются с этим именем; тач-цель 48 lp не уменьшается.
- **Брейкпоинт** `ds.breakpoint.large ≥ 1600` — каноническое имя (R0 §17.5); пометка `[НОВОЕ ИМЯ]` в R-4 §1.1 относится только к именам `compact|medium|expanded`.
- **Радиус `r-xl 20`** — только карточка входа/регистрации (SCR-01…SCR-04, SCR-08 на medium+); остальные диалоги и листы — `r-lg 16`.
- **Reduce-motion** — crossfade ≤ 80 мс или статичный кадр (R0 §17.5): касается переходов экранов, раскрытия SS/CP и смены раскладки (R-6 — смена класса окна и так без анимации).
- **Телефон** — ввод и отображение `+996 XXX XXX XXX` (16 символов с пробелами), хранение/API — E.164 (R0 §17.2, Q-112). Проверка ширины при масштабе шрифта 1,3× (§9): поле `PhoneField` на compact 360 lp вмещает значение `bodyLg` 16 × 1,3 ≈ 21 lp без переноса и без обрезки префикса.
- **Арифметика** — во всех примерах: 16 850,00 − 842,50 (5 %) = **16 007,50 сом** (как в SCR-10 §4).
- **Разделение обязанностей** (R0 §17.2, D-15): у `admin`/`owner` на SCR-24/SCR-30/SCR-34 кнопка «Принять оплату» не выводится — раскладка этих экранов для них соответствует просмотровому варианту (освободившееся место не резервируется).
- **Фото товаров** (R0 §17.2, D-30): варианты **160 / 400 / 1200 px, WebP** — миниатюры `CartLine`/`ImageGallery` (40–64 lp) и `ProductCardCompact` берут 160; `ProductCardGrid`/`ProductCardList` (до ≈ 280 lp) — 400; `ImageGallery` SCR-14 (≤ 480 lp, с учётом плотности пикселей 2–3×) — 1200. Размеры 200/800/1600 (R5 §6.6) не используются `[ТИПОВО]` (выбор по ширине контейнера × `devicePixelRatio`).
- **Тени** — по R0 §8.3 (`elev1…elev3`; приоритет над R4 §5.4, R0 §17.5): popover — `elev2`, диалоги/SS/модальные окна — `elev3`.
