### 2.4. Выжимка паттернов для «Оптомстрой»

1. **Плотность**: POS-экран ≥ 1024 px — три зоны (навигация/каталог/корзина) постоянно видимы; карточки 5–6 в ряд при ≥ 1280 px, 4 при 1024, 2–3 на планшете 600–1024, 2 на телефоне (или список).
2. **Тач-цели**: все интерактивные элементы ≥ 48×48 dp на тач-устройствах (Material) и ≥ 44 pt на iPad; на десктопе с мышью допускается 32–36 px при плотности «compact», но кнопки «+ Добавить», «+/−», «Создать заказ» оставлять ≥ 44 px, т. к. POS-мониторы часто сенсорные [ТИПОВО].
3. **Корзина**: справа на широких экранах (как в макетах, Loyverse/Square — аналогично «ticket panel»); на телефоне — плавающая кнопка-итог внизу (счётчик + сумма) → bottom sheet/экран корзины.
4. **Быстрый ввод количества**: повторный тап «+ Добавить» → степпер; долгое нажатие/тап по числу → числовая клавиатура (нампад как в Odoo); кратность упаковки и единицы из 1С — валидация шага.
5. **Поиск + штрихкод**: одно поле «название / артикул / штрихкод», иконка сканера; аппаратный сканер в режиме клавиатуры должен завершать ввод суффиксом (Enter) и не открывать лишние окна (типовая проблема HID-сканеров, см. 2.1) [ТИПОВО].
6. **Одна рука на телефоне**: основные действия (поиск, корзина, «Добавить») в нижней трети; категории — горизонтальные чипы под поиском; сайдбар — drawer.
7. **Цвет для статусов**: только семантические цвета + иконка + текст (красно-зелёная пара неразличима для ~8 % мужчин — раздел 3.4).
8. **Скелетоны/пустые состояния**: по NN/g — скелетон только для сетки каталога и списков; пустые состояния с действием.
9. **Избранное на телефоне вместо настраиваемых страниц** (Loyverse) — совпадает с «Избранное 27» на макете.
10. **Варианты товара**: плитка-родитель → селектор варианта (проектное решение [ТИПОВО]; в Lightspeed quick key может ссылаться на родительский товар с вариантами, поведение тапа не подтверждено — 2.1) — для смесителей/труб с размерами и цветами.

## 3. Два варианта палитры и программная проверка контраста

### 3.1. Принципы (для обоих вариантов)

- Нейтральная рабочая база: фон не чисто белый (#F4F5F7), поверхности белые, текст не чисто чёрный (#1B1F2A) — снижает блеск и утомляемость при 8–10-часовой смене [ТИПОВО: практика дизайн-систем, требует проверки на месте].
- Яркое освещение торгового зала/склада → высокий контраст текста (цель AAA 7:1 для основного текста, ≥ 4.5:1 для вторичного), крупные цифры цен/остатков.
- Семантика: **красный только ошибка/долг/нет в наличии**, **зелёный — успех/в наличии/оплачено**, **жёлто-янтарный — предупреждение/мало/просрочено**, **серо-синий — информация/синхронизация**.
- Бренд-акцент используется для интерактивных элементов (primary) только если он проходит 4.5:1 с текстом на нём.
- Тёмная тема — вне Release 1 (вся работа при дневном освещении); токены спроектированы так, чтобы её добавить позже [НЕ ПОДТВЕРЖДЕНО: потребность].

**Конфликт «оранжевый бренд vs warning» и решение:** (1) бренд-оранжевый никогда не используется как цвет статуса; (2) warning переводится в жёлто-охристый (#8A6A00 текст, #FEF9C3 фон) и **всегда** сопровождается иконкой «треугольник !» и текстом; (3) бейджи остатков «мало» используют warning-container + текст, а не оранжевую заливку; (4) primary-оранжевый ограничен: логотип, главная CTA, активный пункт навигации, прогресс. Симуляция дальтонизма (3.4) показывает, что primary-text #B04E00 и warning #8A6A00 при протан/дейтеранопии сливаются (ΔE 7/3) — это дополнительный аргумент против оранжевого как интерактивного цвета.

### 3.6. Рекомендация

**Рекомендуется вариант A «Синий» как рабочая интерактивная палитра, в комбинированной схеме:**

- нейтральная рабочая база (background #F4F5F7, surface #FFFFFF, text #1B1F2A / #5A6373);
- интерактивный primary — синий #0053FA (CTA, ссылки, выбранные элементы, фокус);
- семантические цвета — success #15803D, warning #B45309, error #C62828, info #0E6A8E;
- **оранжевый #FF8700 — только брендовый акцент**: логотип, splash, персонаж авторизации (детали одежды/аксессуар), иллюстрации пустых состояний, подчёркивание активной вкладки в шапке — **только как дополнительный признак**: основной индикатор активной вкладки — текст вкладки text-primary #1B1F2A / вес 600 против text-secondary 500 у неактивных (оранжевая линия #FF8700 на белом даёт 2.41:1 и по 3.4 не может быть единственным индикатором, WCAG 1.4.11); если нужен один цветовой индикатор — подчёркивание primary #0053FA. Никогда — как цвет статуса, цены или единственной обводки.

Обоснование: A проходит AA для всех текстовых и нетекстовых пар без дополнительных «текстовых» версий цвета; не конфликтует с семантикой; подтверждён макетами; оранжевый сохраняет узнаваемость бренда без потери доступности. Если заказчик подтвердит, что оранжевый логотип — единственный актуальный бренд и синий недопустим, применяется вариант B со всеми ограничениями 3.3 (тёмный текст на CTA, #B04E00 для текста, жёлтый warning).

Решение заказчика требуется по: (1) актуальный логотип; (2) допустимость синего как интерактивного цвета при оранжевом логотипе.

## 5. Сетка, отступы, размеры, иконки

### 5.1. Базовая сетка и отступы

- Базовый модуль **4 px**, рабочие шаги 8 px: токены space-1…space-10 = 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.
- Внутренние отступы карточки 12 (compact) / 16 (standard); между карточками 12 (compact) / 16; боковые поля экрана 16 (телефон), 24 (планшет), 24–32 (десктоп).
- Высота строк списка: 48 (compact), 56 (standard), 72 (с миниатюрой 40–48 px и двумя строками текста).

### 5.6. Плотность для POS

Два режима плотности через токен `density`: **standard** (телефон, планшет: строки 56, кнопки M 44) и **compact** (POS ≥ 1024 с мышью/сенсорным монитором: строки 48, карточки 12 px padding, кнопки 40 визуально/44 цель). Переключение автоматически по классу окна с возможностью ручного выбора в настройках.

## 7. Анимации

### 7.1. Принципы

- Длительности по Material 3 (Flutter `Durations`): short 50–200 мс, medium 250–400, long 450–600, extra-long 700–1000 [ПОДТВЕРЖДЕНО: https://api.flutter.dev/flutter/material/Durations-class.html]. Для POS: **150 мс** — микро-реакции (hover, pressed, чекбокс), **200 мс** — появление/скрытие элементов, смена состояния кнопки, **300 мс** — переходы экранов, bottom sheet, добавление в корзину; **≥ 500 мс** — только splash и персонаж.
- Кривые (Flutter `Easing`): standard `Cubic(0.2, 0, 0, 1)`; standardDecelerate `Cubic(0, 0, 0, 1)` — появление; standardAccelerate `Cubic(0.3, 0, 1, 1)` — исчезновение; emphasizedDecelerate `Cubic(0.05, 0.7, 0.1, 1)` — splash/персонаж [ПОДТВЕРЖДЕНО: https://github.com/flutter/flutter/blob/master/packages/flutter/lib/src/material/motion.dart].
- Анимация никогда не блокирует ввод: следующий тап обрабатывается во время анимации; нет «мигания» (частота изменений яркости < 3 Гц); перемещение не больше 24–48 lp для списков.
- **Reduce motion**: в Flutter `MediaQuery.disableAnimationsOf(context)` соответствует Android «Remove animations»; iOS «Reduce Motion» приходит отдельным флагом `AccessibilityFeatures.reduceMotion` и не устанавливает `disableAnimations` [ПОДТВЕРЖДЕНО: https://api.flutter.dev/flutter/widgets/MediaQueryData/disableAnimations.html]. Политика: при любом из флагов — длительности → 0–80 мс, перемещения и масштаб → кроссфейд, шиммер → статичный, персонаж → статичные кадры состояний; плюс ручной переключатель «Уменьшить анимации» в настройках приложения.

## 8. Анализ количества действий для типовых задач

Предположения: пользователь авторизован; экран каталога открыт; «тап» = касание/клик; ввод текста считается одним шагом «ввод». Для POS-экрана ≥ 1024 (3 колонки) и телефона.

| Задача | Экран | Шаги | Тапы (без ввода текста) | Примечание |
|---|---|---|---|---|
| Найти товар и добавить 3 шт. в корзину | POS ≥ 1024 | 1) тап в поиск; 2) ввод «F4252» или скан; 3) тап «+ Добавить» на карточке; 4) тап «+» ×2 (кнопка превратилась в степпер) | **4** (1 + 1 + 2); со сканером: **3** | Альтернатива: долгий тап на числе → нампад «3» → OK = 4 тапа, выгодно при qty ≥ 5. Корзина обновляется без перехода |
| То же | Телефон | 1) тап в поиск (поле закреплено сверху); 2) ввод/скан; 3) тап «+»; 4) «+» ×2 | **4**; со сканером **3** | Корзина не открывается; итог виден в нижней панели |
| То же через категорию (без поиска) | POS | 1) тап категории; 2) тап «+ Добавить»; 3) «+» ×2 | **4** + прокрутка | Сортировка/фильтр при необходимости +2 |
| Оформить заказ (клиент существует, самовывоз, наличные, без изменения печати) | POS | 1) «Создать заказ»; 2) поиск клиента: тап + ввод телефона; 3) тап строки клиента; 4) «Далее»; 5) «Самовывоз» (если не по умолчанию); 6) «Далее»; 7) «Наличными»; 8) «Далее»; 9) «Создать заказ» | **8–9** | Макет объединяет шаги на одном экране (десктоп) — тогда: 1) «Создать заказ»; 2–3) клиент; 4) самовывоз; 5) наличные; 6) «Создать заказ» = **6**. Рекомендация: на ≥ 1024 — одноэкранная форма с 4 секциями (как макет), на телефоне — 4 шага |
| Оформить заказ | Телефон | 1) панель-итог → корзина; 2) «Оформить»; 3–4) клиент; 5) «Далее»; 6) получение «Далее» (по умолчанию самовывоз); 7) оплата → «Далее»; 8) «Создать заказ» | **8** | Значения по умолчанию (последний способ оплаты/получения) снижают до 6 |

| То же | Телефон | 1) вкладка «Клиенты»; 2) тап поиска + ввод; 3) тап строки | **3** + ввод | Долг в строке списка → 2 + ввод |

# WCAG 2.x contrast calculator + colour-vision simulation for Optomstroy palettes
import math, sys
sys.stdout.reconfigure(encoding='utf-8')

def h2rgb(h):
    h = h.lstrip('#'); return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))

def lin(c):
    c = c / 255
    return c / 12.92 if c <= 0.03928 else ((c + 0.055) / 1.055) ** 2.4

def lum(h):
    r, g, b = h2rgb(h); return 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b)

def ratio(a, b):
    la, lb = lum(a), lum(b); hi, lo = max(la, lb), min(la, lb); return (hi + 0.05) / (lo + 0.05)

def grade(r):
    n = 'AAA' if r >= 7 else ('AA' if r >= 4.5 else 'FAIL')

    return n, l

# ---- colour vision deficiency simulation (Machado et al. 2009 matrices, severity 1.0, linear RGB)
M = {'protanopia':[[0.152286,1.052583,-0.204868],[0.114503,0.786281,0.099216],[-0.003882,-0.048116,1.051998]],
     'deuteranopia':[[0.367322,0.860646,-0.227968],[0.280085,0.672501,0.047413],[-0.011820,0.042940,0.968881]],
     'tritanopia':[[1.255528,-0.076749,-0.178779],[-0.078411,0.930809,0.147602],[0.004733,0.691367,0.303900]]}

def sim(h, kind):
    r, g, b = [lin(c) for c in h2rgb(h)]; m = M[kind]
    out = [m[i][0]*r + m[i][1]*g + m[i][2]*b for i in range(3)]
    return [min(1, max(0, v)) for v in out]

def lin2lab(rgb):
    r, g, b = rgb
    X = 0.4124*r + 0.3576*g + 0.1805*b; Y = 0.2126*r + 0.7152*g + 0.0722*b; Z = 0.0193*r + 0.1192*g + 0.9505*b
    def f(t): return t ** (1/3) if t > 0.008856 else 7.787*t + 16/116
    fx, fy, fz = f(X/0.95047), f(Y/1.0), f(Z/1.08883)
    return (116*fy - 16, 500*(fx - fy), 200*(fy - fz))

def dE(a, b): return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))

def rgb2hex_lin(rgb):
    def g(c):
        c = max(0, min(1, c)); return round(255 * (12.92*c if c <= 0.0031308 else 1.055 * c ** (1/2.4) - 0.055))
    return '#%02X%02X%02X' % tuple(g(c) for c in rgb)

print('|---|---|---|---|---|---|')
