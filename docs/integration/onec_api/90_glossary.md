# Глоссарий

| Термин | Значение |
|---|---|
| POS, «Оптомстрой POS» | кассовая система магазина: приложение для продавцов, кассиров, администратора и покупателей (касса Windows, Android, iOS) и сервер магазина |
| backend, сервер POS | серверная часть POS. Единственный участник, который обращается к 1С |
| Покупатель | клиент магазина, который сам оформляет заказ в мобильном приложении. Для 1С его заказ — обычный «Заказ клиента» |
| Расширение конфигурации | механизм платформы 1С для доработок без изменения типовой конфигурации. Здесь — расширение «OptomstroyPOS» с назначением «Адаптация» и префиксом `POS_` |
| HTTP-сервис | объект 1С, который принимает HTTP-запросы по адресу `/hs/<корень>/…`. Здесь — `POS_HTTPСервисPOS` с корнем `pos` |
| План обмена «POS» | объект 1С, который регистрирует изменения нужных POS объектов для узла `POS`. Через него POS получает только изменившиеся данные |
| Регистрация изменений | запись в таблице изменений плана обмена о том, что объект создан, изменён, помечен на удаление или удалён. Снимается только по номеру подтверждённого сообщения |
| Сообщение обмена (пакет) | набор зарегистрированных изменений с номером `N+1`. Выдаётся страницами по `cursor` |
| Подтверждение (ack) | вызов `POST /changes/ack`: POS сообщает, что полностью применил сообщение, и 1С снимает регистрацию по его номеру |
| Перерегистрация | вызов `POST /changes/reregister`: 1С заново регистрирует весь состав плана обмена для полной перезагрузки данных в POS |
| `ObjectDeletion` | элемент сообщения обмена о физическом удалении объекта в 1С |
| DataVersion, `dataVersion` | версия данных объекта 1С (`ВерсияДанных`). По ней POS понимает, изменился ли объект |
| `ref`, `Ref_Key`, ссылка | GUID ссылки объекта 1С (`УникальныйИдентификатор`) в нижнем регистре |
| `externalId` | UUID объекта, который присваивает POS: заказа, платежа, клиента, заявки на возврат. Ключ защиты от дублей при создании объектов в 1С |
| Идемпотентность, защита от дублей | свойство метода: повторный запрос с тем же `externalId` не создаёт второй объект, а возвращает уже созданный |
| Регистр внешних идентификаторов | регистр сведений расширения `POS_ВнешниеИдентификаторыPOS`: связь `externalId` и типа объекта со ссылкой на объект 1С |
| Очередь отправки, outbox | очередь на сервере POS, из которой заказы, оплаты, новые клиенты, заявки на возврат и отмены заказов отправляются в 1С с повторами |
| `X-Request-Id` | UUID запроса со стороны POS. Нужен, чтобы найти один и тот же запрос в журналах обеих сторон. Ключом защиты от дублей не является |
| `X-POS-Client-Key` | второй ключ доступа к HTTP-сервису, передаётся в каждом запросе вместе с паролем пользователя `pos_hs` |
| Технический пользователь | пользователь информационной базы без интерактивного входа, через которого работает интеграция: `pos_hs` для HTTP-сервиса и `pos_integration` для OData |
| Привилегированный режим | выполнение кода 1С без проверки прав пользователя. В расширении разрешён только в общем модуле `POS_Сервер` после проверки ключа и входных данных |
| Временная ошибка | ошибка, после которой запрос можно повторить: блокировка, обновление, сбой, недоступность банка (`POS_E_LOCKED`, `POS_E_INTERNAL`, `POS_E_MAINTENANCE`, `POS_E_QR_UNAVAILABLE`) |
| Ошибка данных, бизнес-отказ | ошибка, которую повтор не исправит: неверное заполнение, недопустимое состояние, дубль клиента |
| Неизвестный результат | таймаут или обрыв связи: запрос мог выполниться в 1С. POS повторяет его с тем же `externalId` |
| Стандартный OData | встроенный в платформу REST-интерфейс 1С (`/odata/standard.odata/`). В проекте — только чтение |
| `$metadata` | описание объектов, опубликованных через OData (файл XML) |
| БСП | Библиотека стандартных подсистем: контактная информация, присоединённые файлы, настройки OData |
| `ETag` | метка версии файла картинки (SHA-256 содержимого или дата модификации и размер). При совпадении 1С отвечает 304 без тела |
| Динамический QR | QR на конкретную сумму конкретного заказа, создаваемый по запросу через интеграцию 1С с банком |
| Статический QR | постоянный QR магазина без суммы. Оплату по нему кассир подтверждает вручную |
| ПКО | приходный кассовый ордер |
| Соглашение | условия работы с клиентом в 1С: вид цены, скидка, отсрочка, лимит долга |
| Свободный остаток | остаток на складе за вычетом резервов |
| Розничный покупатель | покупатель без своей карточки клиента в 1С. POS отправляет его заказ без ссылки на клиента |
| step-up | повторное подтверждение сотрудником своей личности перед чувствительной операцией в POS, например ручным подтверждением оплаты. Выполняется в POS, 1С не касается |
| Тестовая копия | копия рабочей базы 1С с обезличенными данными для разработки и приёмки |
| Контрольный пример (КП) | набор из 20 шагов КП-1…КП-20 для приёмки API на тестовой копии |
| Комплект поставки | файл `.cfe`, инструкция, описание фактических имён, журнал изменений, набор запросов и протокол |
| `.cfe` | файл расширения конфигурации 1С |
| Контракт | машинное описание API `onec-http-service.v1.yaml` (OpenAPI 3.0) — источник истины путей, полей и кодов |
| Стенд-эмулятор | программа, которая имитирует HTTP-сервис 1С на синтетических данных |
| LAN, VPN, WireGuard | способы связи сервера POS с 1С: локальная сеть магазина или защищённый туннель, который поднимает сторона магазина |
| Вариант «1С вызывает POS» | резервный способ связи: регламентное задание расширения само обращается к серверу POS. В этот запрос не входит |
| KGS, сом | валюта Кыргызстана; 1 сом = 100 тыйынов |
| ISO 8601 | формат даты и времени, здесь — со смещением Бишкека: `2026-10-21T14:05:00+06:00` |
| p50, p95 | медиана и 95-й процентиль времени ответа: 95 % ответов не дольше этого значения |
