# Методы группы Б: продажи и клиенты

В этом разделе описаны методы HTTP-сервиса расширения «OptomstroyPOS», через которые POS работает с продажами и клиентами: проверяет корзину, создаёт и отменяет «Заказ клиента», читает статусы заказов, ищет и создаёт клиентов, получает долг клиента. Все методы вызывает сервер POS (backend), а не кассы и не телефоны покупателей. 1С сама POS не вызывает.

Точные пути, поля, типы и коды ответов заданы в машинном контракте `onec-http-service.v1.yaml`, он источник истины. Если текст ниже расходится с контрактом, прав контракт. Сообщите нам о расхождении. Имена объектов 1С даны для «Управление торговлей 11», «Комплексная автоматизация 2» и ERP и помечены «типово — уточнить», потому что конфигурация вашей базы нам пока неизвестна (Q-010: конфигурация, релиз, платформа).

## Состав группы и общие правила

### Перечень методов группы

| Метод и путь | Что делает | Кто и когда вызывает | Защита от дублей |
|---|---|---|---|
| `POST /pos/v1/check` | проверка корзины: цены, свободные остатки, долг и лимит клиента, при необходимости автоскидки 1С | сервер POS синхронно, при оформлении заказа | только чтение, ничего не записывает |
| `POST /pos/v1/orders` | создать «Заказ клиента» | очередь отправки сервера POS сразу после оформления заказа | по `externalId` заказа |
| `POST /pos/v1/orders/{uuid}/cancel` | отменить заказ, созданный из POS | очередь отправки сервера POS после отмены заказа в POS | по `externalId` заказа |
| `GET /pos/v1/orders/{uuid}/status` | статус одного заказа | сервер POS при открытии карточки заказа и при ручной привязке | только чтение |
| `POST /pos/v1/orders/status` | статусы до 200 заказов одним запросом | фоновая синхронизация, каждые 5 минут | только чтение |
| `GET /pos/v1/customers?phone=…` | поиск клиентов по телефону | сервер POS при создании клиента и при регистрации покупателя | только чтение |
| `POST /pos/v1/customers` | создать клиента без дублей по телефону | очередь отправки сервера POS после создания клиента в POS | по `externalId` клиента и по телефону |
| `GET /pos/v1/customers/{ref}/receivables` | долг клиента: сальдо, просрочка, документы, лимит и отсрочка | фоновая синхронизация каждые 30 минут и по запросу кассира | только чтение |

`{uuid}` в путях заказов — это `externalId` заказа POS. `{ref}` в пути долга — ссылка партнёра 1С (`Ref_Key`, GUID в нижнем регистре).

### Заголовки запроса и ответа

Полностью правила аутентификации и журналирования описаны в разделе «Общие требования к API». Для методов этой группы они такие.

| Заголовок | Где | Обязательно | Описание |
|---|---|---|---|
| `Authorization` | запрос | да | `Basic` для пользователя ИБ `pos_hs` или `Bearer` с JWT, если платформа поддерживает JWT (выбор — при приёмке) |
| `X-POS-Client-Key` | запрос | да | второй ключ доступа. Без него — ответ 401, даже при верном пароле |
| `X-Request-Id` | запрос | да | UUID запроса. 1С пишет его в журнал запросов и возвращает в ответе и в поле `requestId` тела ошибки |
| `Content-Type` | запрос с телом | да | `application/json; charset=utf-8` |
| `Accept` | запрос | да | `application/json` |
| `X-POS-API-Version` | ответ | да | для этой версии API всегда `1` |
| `X-Request-Id` | ответ | да | то же значение, что пришло в запросе |

Заголовок `Idempotency-Key` к 1С не передаётся. Ключ защиты от дублей — поле `externalId` в теле запроса (для заказа и клиента) или в пути (для отмены). `X-Request-Id` ключом защиты от дублей не является. При повторной отправке того же заказа из очереди он может совпадать с предыдущим запросом, а может отличаться. Это не ошибка.

### Форматы значений

- UUID и ссылки 1С — строки в нижнем регистре: `"c3d4e5f6-0000-4000-8000-000000000001"`.
- Деньги — строка с точкой и двумя знаками: `"4465.00"`. Процент скидки — так же: `"5.00"`.
- Количество — строка с точкой и тремя знаками: `"2.000"`.
- Дата и время — ISO 8601 со смещением Бишкека: `"2026-10-21T13:40:00+06:00"`.
- Телефон — формат E.164: `"+996700000001"`.
- Валюта — код ISO 4217. Сейчас только `KGS`.
- `null` допустим только у необязательных полей. Неизвестные поля получатель игнорирует, поэтому 1С может добавлять в ответ свои поля. Удалять и переименовывать поля нельзя.

### Защита от дублей при создании объектов

Методы `POST /pos/v1/orders` и `POST /pos/v1/customers` создают объекты в 1С. POS повторяет запрос после таймаута, сбоя сети или временной ошибки, и повтор всегда идёт с тем же `externalId`. Поэтому расширение обрабатывает такой запрос в одном порядке.

1. Найти `externalId` в регистре сведений `POS_ВнешниеИдентификаторыPOS` с учётом `ТипОбъекта` (`Заказ` или `Клиент`).
2. Если запись найдена — вернуть **200** с уже существующим объектом и ничего не создавать. Пометка удаления документа на ответ 200 не влияет: возвращается тот же документ с `deletionMark=true`.
3. Если запись не найдена — создать объект и запись регистра **в одной транзакции** и вернуть **201**.
4. Параллельные запросы с одним `externalId` должны дать ровно один объект. Используйте управляемую блокировку по `ВнешнийИд` или иной способ на ваше усмотрение. Проверка при приёмке: 10 одновременных запросов с одним `externalId` создают один документ.

Записи регистра `POS_ВнешниеИдентификаторыPOS` не удаляются при пометке документа на удаление. Удалить их можно только вместе с удалением документа администратором 1С.

### Ошибки: временные и неисправимые

Тело ошибки — единый формат для всех методов. Поле `message` — текст для журнала **без персональных данных**: без телефонов, ИНН, сумм долга.

```json
{
  "code": "POS_E_MAINTENANCE",
  "message": "Идёт обновление конфигурации",
  "requestId": "0192f5c3-0000-7000-8000-000000000001"
}
```

POS делит ошибки на два вида и по-разному на них реагирует.

- **Временные** — `POS_E_LOCKED` (HTTP 423 или 503), `POS_E_INTERNAL` (500), `POS_E_MAINTENANCE` (503), а также таймаут и обрыв связи. Запрос на запись POS повторяет из очереди с паузами 1, 2, 5, 15 и 60 минут, затем раз в час. Попыток — не больше 20, срок — не больше 24 часов, после этого POS сообщает администратору. Методы чтения POS повторяет по своему расписанию.
- **Ошибки данных и бизнес-отказы** — `POS_E_BAD_REQUEST` (400), `POS_E_NOT_FOUND` (404), `POS_E_DUPLICATE`, `POS_E_STATE`, `POS_E_STOCK`, `POS_E_PRICE`, `POS_E_CREDIT` (409), `POS_E_VALIDATION` (422). Такой запрос POS автоматически не повторяет.
- **Ошибки доступа** — `POS_E_UNAUTHORIZED` (401) и `POS_E_FORBIDDEN` (403). POS не повторяет запрос до исправления учётных данных или прав и сразу сообщает администратору.

Ответы 401 и 503 с кодом `POS_E_MAINTENANCE` возможны в любом методе. Ниже в таблицах ошибок они перечислены коротко.

Если расширение отключено или идёт обновление конфигурации, отвечайте `503 POS_E_MAINTENANCE`. Если база в монопольном режиме, отвечайте `503 POS_E_LOCKED`. Если нужный объект заблокирован другим сеансом, отвечайте `423 POS_E_LOCKED`. Ни в одном из этих случаев нельзя записывать документ частично.

## Проверка корзины и заказы клиента

### POST /pos/v1/check — проверка корзины перед оформлением заказа

#### Назначение

Когда продавец или кассир подтверждает заказ, POS быстро сверяет корзину с 1С. Метод возвращает по каждой строке актуальную цену по виду цены или по соглашению клиента, свободный остаток на складе заказа с учётом резервов, остатки на всех складах и признак доступности. Для продажи в долг метод возвращает сальдо, просрочку и доступный лимит клиента. Если POS попросит, метод возвращает итог с автоматическими скидками 1С. Метод **ничего не записывает** в базу: не создаёт документы и не ставит резервы.

#### Когда вызывается и как часто

- При подтверждении заказа и на шаге «Оплата» перед подтверждением. Если корзина не менялась, POS повторно использует результат проверки в течение 60 секунд.
- Ожидаемая частота — 20–100 вызовов в час. В корзине обычно 5–30 строк, максимум 100.
- Если 1С не ответила за 6 секунд, вернула 5xx или `POS_E_MAINTENANCE`, POS оформляет заказ по последним загруженным данным с пометкой «данные могли устареть». Поэтому для этого метода важнее скорость, чем полнота.

#### Запрос

`POST /pos/v1/check`, заголовки — см. «Заголовки запроса и ответа». Тело — объект.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `customerRef` | строка (ссылка) или `null` | да, допускается `null` | партнёр 1С. `null` — розничный покупатель без карточки |
| `priceListRef` | строка (ссылка) или `null` | да, допускается `null` | вид цены (`Справочник.ВидыЦен`, типово — уточнить). `null` — цена по соглашению клиента или вид цены по умолчанию |
| `warehouseRef` | строка (ссылка) | да | склад продажи (`Справочник.Склады`, типово — уточнить) |
| `paymentMethod` | строка | да | способ оплаты: `cash` (наличные), `qr_bakai` (оплата по QR), `credit` (в долг) |
| `calculateDiscounts` | логическое | да | `true` — рассчитать итог с автоматическими скидками 1С и вернуть блок `totals` |
| `lines` | массив объектов | да | строки корзины, от 1 до 100. Состав — в следующей таблице |

Строка `lines[]`.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `productRef` | строка (ссылка) | да | номенклатура (`Справочник.Номенклатура`, типово — уточнить) |
| `variantRef` | строка (ссылка) или `null` | да, допускается `null` | характеристика номенклатуры. `null` — товар без характеристик |
| `packagingRef` | строка (ссылка) или `null` | да, допускается `null` | упаковка (`Справочник.УпаковкиЕдиницыИзмерения`, типово — уточнить). `null` — базовая единица |
| `quantity` | строка (количество) | да | количество в строке. Единица количества при указанной упаковке и правила кратности уточняются по Q-021 (упаковки, кратность, минимальная партия) |

Цену POS в запрос не передаёт. Цену и остаток считает 1С.

#### Ответ

**200** — проверка выполнена. Замечания по строкам (нет остатка, нет цены, нарушена кратность, долг заблокирован) — **не ошибка**: ответ всё равно 200, замечания передаются в `issues`. Код 201 метод не возвращает.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `checkedAt` | строка (дата-время) | да | момент, на который 1С рассчитала цены и остатки |
| `lines` | массив объектов | да | результат по каждой строке запроса, в том же порядке. Состав — в следующей таблице |
| `receivables` | объект или `null` | да, допускается `null` | блок долга клиента. Заполняется только при указанном `customerRef` и `paymentMethod=credit`, иначе `null` |
| `totals` | объект или `null` | да, допускается `null` | итог 1С с автоскидками. Заполняется только при `calculateDiscounts=true`, иначе `null` |
| `issues` | массив объектов | да | замечания ко всей корзине (например, по долгу). Пустой массив, если замечаний нет |

Строка `lines[]` ответа.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `productRef` | строка (ссылка) | да | номенклатура из запроса |
| `variantRef` | строка (ссылка) или `null` | да, допускается `null` | характеристика из запроса |
| `price` | строка (деньги) или `null` | да, допускается `null` | актуальная цена за единицу по виду цены или соглашению клиента. `null` — цены нет, тогда в `issues` строки нужен код `VARIANT_UNAVAILABLE` |
| `available` | строка (количество) | да | свободный остаток на складе `warehouseRef`: остаток минус резервы |
| `onHand` | строка (количество) | да | остаток на складе `warehouseRef` |
| `reserved` | строка (количество) | да | зарезервировано на складе `warehouseRef` |
| `isAvailable` | логическое | да | `true` — строку можно продать в запрошенном количестве |
| `warehouses` | массив объектов | да | свободный остаток по всем складам. Элемент — `warehouseRef` (ссылка) и `available` (количество). Склады с пометкой удаления не включаются |
| `issues` | массив объектов | да | замечания к строке. Элемент — объект с полем `code`. Пустой массив, если замечаний нет |

Блок `receivables` в `/check` содержит те же поля итога, что и ответ метода долга `GET /pos/v1/customers/{ref}/receivables`, но без списка документов: `snapshotAt`, `balance`, `overdueAmount`, `overdueDays`, `creditAllowed`, `creditLimit`, `creditDays`, `creditAvailable`. Смысл полей — в описании метода долга ниже.

Блок `totals`.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `subtotal` | строка (деньги) | да | сумма строк до скидок |
| `discount` | строка (деньги) | да | сумма скидок 1С |
| `total` | строка (деньги) | да | итог к оплате по расчёту 1С |
| `currency` | строка | да | валюта, `KGS` |

Коды замечаний `issues[].code` — ровно эти значения, POS передаёт их в приложение без перекодирования.

| Код | Где | Когда выставлять |
|---|---|---|
| `STOCK_INSUFFICIENT` | строка | запрошенное количество больше `available` на складе заказа |
| `VARIANT_UNAVAILABLE` | строка | товар или характеристика не продаются: помечены на удаление, нет цены в виде цены |
| `QTY_NOT_MULTIPLE` | строка | количество не кратно упаковке или кратности продажи (Q-021) |
| `QTY_BELOW_MIN` | строка | количество меньше минимальной партии (Q-021) |
| `PRICE_CHANGED` | строка | цена изменилась. Цену POS в запросе нет, поэтому 1С этот код выставлять не обязана: POS сам сравнивает `price` со своей ценой |
| `CREDIT_BLOCKED` | корзина | при `paymentMethod=credit`: у клиента есть просрочка или соглашение не разрешает отсрочку |
| `CREDIT_LIMIT_EXCEEDED` | корзина | при `paymentMethod=credit`: сумма корзины больше доступного лимита `creditAvailable` |

#### Ошибки

| HTTP-код | Код ошибки | Когда | Что делает POS |
|---|---|---|---|
| 400 | `POS_E_BAD_REQUEST` | невалидный JSON, больше 100 строк, неверный формат поля | заказ не оформляет, пишет ошибку в журнал |
| 401 | `POS_E_UNAUTHORIZED` | неверный пользователь, пароль, JWT или `X-POS-Client-Key` | заказ не оформляет, сообщает администратору |
| 403 | `POS_E_FORBIDDEN` | у роли `POS_ИнтеграцияPOS` нет прав на объект | как при 401 |
| 422 | `POS_E_VALIDATION` | неизвестный товар, характеристика, склад или вид цены. В `details.lines[]` — номер строки и текст | заказ не оформляет: «1С отклонила проверку заказа» |
| 423 | `POS_E_LOCKED` | объект заблокирован другим сеансом | считает 1С недоступной: оформляет заказ по последним данным с пометкой «данные могли устареть» |
| 500 | `POS_E_INTERNAL` | исключение встроенного языка | как при 423 |
| 503 | `POS_E_MAINTENANCE` или `POS_E_LOCKED` | расширение отключено, идёт обновление или база в монопольном режиме | как при 423 |

Для продажи в долг правило строже. Если 1С недоступна, а сохранённый в POS снимок долга клиента старше 60 минут, отсутствует или неполон, POS **отказывает в продаже в долг** («данные о долге устарели»). Наличную и QR-продажу POS в этом случае оформляет.

#### Правила на стороне 1С

- Метод только читает данные. Документы не создаются, резервы не ставятся, регистрация изменений плана обмена не меняется.
- Цену получайте типовым механизмом ценообразования: по виду цены `priceListRef`, а если он не задан — по соглашению клиента `customerRef` (`Справочник.СоглашенияСКлиентами`, типово — уточнить). Какой вид цены у розничного покупателя и как выбирается вид цены клиента — Q-121.
- Свободный остаток считайте по складу `warehouseRef` с учётом резервов, например по регистру накопления `СвободныеОстатки` или `ТоварыНаСкладах` (типово — уточнить). Учёт по сериям и назначениям — Q-120.
- Блок `receivables` заполняйте теми же правилами, что и метод долга. Сальдо должно совпадать с отчётом «Задолженность клиентов» на момент `checkedAt`.
- При `calculateDiscounts=true` рассчитайте автоматические скидки типовым механизмом (`Справочник.СкидкиНаценки`, типово — уточнить) так, как они применились бы в «Заказе клиента», и верните итог в `totals`. Наличие автоматических скидок в вашей базе — Q-015.
- Выполняйте чтение в привилегированном режиме кодом общего модуля `POS_Сервер` после проверки ключа и схемы запроса.

#### Пример запроса

```json
{
  "customerRef": "c3d4e5f6-0000-4000-8000-000000000001",
  "priceListRef": "e5f6a7b8-0000-4000-8000-000000000001",
  "warehouseRef": "d4e5f6a7-0000-4000-8000-000000000001",
  "paymentMethod": "credit",
  "calculateDiscounts": false,
  "lines": [
    {
      "productRef": "a1b2c3d4-0000-4000-8000-000000000001",
      "variantRef": "a1b2c3d4-0000-4000-8000-000000000101",
      "packagingRef": null,
      "quantity": "2.000"
    },
    {
      "productRef": "a1b2c3d4-0000-4000-8000-000000000002",
      "variantRef": null,
      "packagingRef": null,
      "quantity": "10.000"
    }
  ]
}
```

### POST /pos/v1/orders — создать «Заказ клиента»

#### Назначение

Создать в 1С документ «Заказ клиента» (`Документ.ЗаказКлиента`, типово — уточнить) из заказа POS. Заказ оформляет продавец, кассир или сам покупатель в приложении. Для 1С это одинаково. POS не создаёт документ 1С в момент оформления: заказ сначала сохраняется в POS, а затем очередь отправки передаёт его в 1С. До ответа 1С продавец видит заказ в состоянии «Отправляется в 1С». Номер 1С и статус появляются после ответа этого метода.

#### Когда вызывается и как часто

- Сразу после оформления заказа в POS, из очереди отправки. Если 1С недоступна, POS повторяет запрос по правилам временных ошибок с тем же `externalId`.
- Если заказ оформлен на нового клиента, POS сначала создаёт клиента методом `POST /pos/v1/customers`. Заказ отправляется только после того, как 1С вернула ссылку клиента.
- Ожидаемая частота — 10–100 заказов в час.

- **201** — документ создан и проведён.
- **200** — заказ с этим `externalId` уже существует, возвращён существующий документ. Ничего не создано. Так же 1С отвечает и после пометки документа на удаление, тогда `deletionMark=true`.

|---|---|---|---|
| `externalId` | строка (UUID) | да | `externalId` из запроса |
| `ref` | строка (ссылка) | да | ссылка документа «Заказ клиента». Без неё POS считает результат неизвестным и повторит запрос |
| `number` | строка | да | номер документа 1С, например `ОС00-004512` |
| `date` | строка (дата-время) | да | дата документа |
| `status` | строка | да | значение статуса заказа 1С. При создании — `НеСогласован` или эквивалент вашей конфигурации |
| `approved` | логическое | да | признак «Согласован» |
| `posted` | логическое | да | документ проведён |
| `deletionMark` | логическое | да | пометка удаления документа на момент ответа |
| `recalculated` | логическое | да | `true` — итог 1С отличается от `totals.total` запроса больше чем на 0,01 сом |
| `totals` | объект | да | **фактические** суммы документа 1С: `subtotal`, `discount`, `total`, `currency` |
| `warnings` | массив строк | да | предупреждения 1С для журнала, например «Применена автоматическая скидка 1С». Пустой массив, если их нет |

**Статусы заказа.** POS не вычисляет статус в 1С, а переводит сырое значение 1С в свой статус. Сейчас POS распознаёт такие значения перечисления `СтатусыЗаказовКлиентов` (типово — уточнить, Q-012). Регистр букв, пробелы и подчёркивания POS не учитывает.

| Значение 1С | Что означает для POS |
|---|---|
| `НеСогласован`, `НаСогласовании` | заказ принят 1С и ждёт согласования |
| `КВыполнению`, `Согласован` | заказ согласован, к выполнению |
| `Закрыт` | заказ закрыт. С проведённой реализацией — выполнен, без реализаций — отменён |

Передавайте имя значения перечисления, например `НеСогласован`. Если в вашей базе используются другие статусы (например, настраиваемые состояния заказов), пришлите их список с описанием — POS добавит соответствие (Q-012). Статус, который POS не распознал, не меняет статус заказа в POS. POS записывает ошибку синхронизации и сообщает администратору.

**Итог 1С — истина.** Суммы POS в 1С «как есть» не записываются. 1С заполняет и пересчитывает документ сама: цены, автоматические скидки, НДС. Если итог 1С отличается от `totals.total` больше чем на 0,01 сом, верните `recalculated=true` и фактические суммы в `totals`. POS сохраняет итог 1С рядом со своим, показывает продавцу и кассиру признак «итог 1С отличается от итога POS» и уведомляет продавца.

#### Ошибки

| HTTP-код | Код ошибки | Когда | Что делает POS |
|---|---|---|---|
| 400 | `POS_E_BAD_REQUEST` | невалидный JSON, не заполнено обязательное поле, неверный формат | задача отправки — «ошибка», без автоповтора. Заказ — «не принят 1С», продавцу — уведомление |
| 401 | `POS_E_UNAUTHORIZED` | неверные учётные данные или ключ | задача отправки остановлена, администратору — тревога. Повтор — вручную после исправления |
| 403 | `POS_E_FORBIDDEN` | нет прав роли | как при 401 |
| 409 | `POS_E_STOCK`, `POS_E_PRICE` или `POS_E_CREDIT` | 1С отклонила заказ по остаткам, ценам или долгу. Только если вы включите такую проверку при создании. По умолчанию её нет | задача отправки — «ошибка» без автоповтора. Заказ — «не принят 1С», продавцу — уведомление |
| 422 | `POS_E_VALIDATION` | не прошла проверка заполнения или проведения типовой конфигурации. В `details.lines[]` — номер строки и текст | как при 409 |
| 423 | `POS_E_LOCKED` | объект заблокирован другим сеансом | повтор позже с тем же `externalId` |
| 500 | `POS_E_INTERNAL` | исключение встроенного языка | повтор позже, после порога — тревога администратору |

#### Правила на стороне 1С

- **Защита от дублей.** Порядок — см. «Защита от дублей при создании объектов». Тип объекта в регистре — `Заказ`. Создание документа, его проведение и запись в `POS_ВнешниеИдентификаторыPOS` — одна транзакция. При любой ошибке транзакция откатывается целиком: в базе не остаётся ни документа, ни записи регистра.
- **Заполнение.** Используйте типовые процедуры конфигурации: заполнение по умолчанию, соглашение, вид цены, склад, организация, пересчёт сумм, НДС, автоматические скидки. Ручную скидку `discountPercent` передайте типовым механизмом ручных скидок для документа и строк.
- **Статус и обеспечение.** Статус при создании — «Не согласован» или эквивалент вашей конфигурации. Статус в запросе POS не передаёт. Строки — с вариантом обеспечения «К обеспечению», резерв не ставится. Кто и как согласует заказы POS — Q-012.
- **Проведение.** Документ проводится в той же транзакции. Ошибки проверки заполнения и проведения возвращайте ответом 422 с номером строки.
- **Комментарий.** В реквизит «Комментарий» запишите строку `POS <externalId>`, чтобы менеджер нашёл заказ поиском. POS уже начинает поле `comment` с этой строки, повторять её не нужно.
- **Права.** Документ создаёт только код общего модуля `POS_Сервер` в привилегированном режиме после проверки ключа и схемы запроса. Прямых прав на запись у роли `POS_ИнтеграцияPOS` нет.
- **Блокировки.** Ставьте управляемую блокировку по `ВнешнийИд` на время проверки и создания. Если нужные данные заблокированы другим сеансом, отвечайте 423 `POS_E_LOCKED`.
- **Регистрация изменений.** Созданный документ регистрируется в плане обмена «POS» как обычно. Элемент `/changes` для него содержит тот же `externalId`.

### POST /pos/v1/orders/{uuid}/cancel — отменить заказ, созданный из POS

#### Назначение

Отменить в 1С «Заказ клиента», созданный из POS, когда заказ отменили в POS: клиент отказался, ошибка продавца. Отмена возможна, только если по заказу **нет проведённых реализаций**. Отмена в 1С — истина. POS считает заказ отменённым в 1С только по ответу этого метода или по статусу документа.

#### Когда вызывается и как часто

- Из очереди отправки, после отмены заказа в POS, если документ в 1С уже создан. Если документа в 1С ещё нет, POS отзывает отправку заказа и этот метод не вызывает.
- Ожидаемая частота — единицы в день.

#### Запрос

`POST /pos/v1/orders/{uuid}/cancel`, заголовки — см. «Заголовки запроса и ответа». Ключ защиты от дублей — `{uuid}` в пути.

| Параметр или поле | Где | Тип | Обязательно | Описание |
|---|---|---|---|---|
| `uuid` | путь | строка (UUID) | да | `externalId` заказа POS |
| `reason` | тело | строка | да | причина отмены для документа 1С, например «Клиент отказался» |

#### Ответ

**200** — заказ отменён или уже был отменён. Тело — текущее состояние заказа в формате ответа метода `GET /pos/v1/orders/{uuid}/status` (таблица полей — в описании этого метода). Признак отмены — `status` отмены вашей конфигурации (типово `Закрыт`) или `deletionMark=true`. Код 201 метод не возвращает.

#### Ошибки

| HTTP-код | Код ошибки | Когда | Что делает POS |
|---|---|---|---|
| 400 | `POS_E_BAD_REQUEST` | невалидный JSON, нет `reason`, `uuid` — не UUID | задача отмены — «ошибка», без автоповтора |
| 401, 403 | `POS_E_UNAUTHORIZED`, `POS_E_FORBIDDEN` | доступ | задача остановлена, администратору — тревога |
| 404 | `POS_E_NOT_FOUND` | заказа с таким `externalId` в 1С нет | задача — «ошибка» без автоповтора. Статус заказа в POS не меняется, администратору — уведомление |
| 409 | `POS_E_STATE` | по заказу есть проведённая реализация или документ в состоянии, которое не позволяет отмену. Документ не меняется | задача — «ошибка» без автоповтора. Статус заказа не меняется, автору отмены — уведомление |
| 423 | `POS_E_LOCKED` | документ заблокирован другим сеансом | повтор позже |
| 500 | `POS_E_INTERNAL` | исключение встроенного языка | повтор позже |
| 503 | `POS_E_MAINTENANCE` или `POS_E_LOCKED` | обновление или монопольный режим | повтор позже |

#### Правила на стороне 1С

- Найдите документ по `externalId` в регистре `POS_ВнешниеИдентификаторыPOS` (тип `Заказ`). Не нашли — 404.
- Проверьте, что по заказу нет проведённых документов «Реализация товаров и услуг» (`Документ.РеализацияТоваровУслуг` с этим заказом в основании, типово — уточнить). Есть — 409 `POS_E_STATE`, документ не меняйте.
- Отмените заказ по правилам вашей базы: статус «Закрыт» с заполненной причиной отмены (реквизит `ПричинаОтмены`, типово — уточнить) или пометка удаления. Запишите текст `reason` в причину отмены или в «Комментарий». Как отменяют заказы в вашей базе — Q-012.
- POS считает заказ отменённым в 1С, если статус `Закрыт` и проведённых реализаций нет, или если `deletionMark=true`.
- Повторная отмена уже отменённого заказа — ответ 200 с тем же состоянием, без изменений документа.
- Изменение документа выполняет только код `POS_Сервер` в привилегированном режиме, в одной транзакции с управляемой блокировкой документа.

```json
}
```

```json
  "ref": "b2c3d4e5-0000-4000-8000-000000000011",
```

Отдельных требований нет. Метод вызывается из очереди, POS ждёт ответ не дольше 30 секунд.

### GET /pos/v1/orders/{uuid}/status — статус одного заказа

#### Назначение

Вернуть текущее состояние одного заказа POS в 1С: ссылку, номер, дату, статус, признак согласования, состояние выполнения, сумму и перечень реализаций по заказу. По этим данным POS показывает продавцу и покупателю статус заказа: на согласовании, к оплате, к отгрузке, отгружен, отменён. Ответ без кэширования: изменение в 1С сразу видно в ответе.

#### Когда вызывается и как часто

- При открытии карточки заказа в POS, когда нужно свежее состояние.

### POST /pos/v1/orders/status — статусы заказов пакетом

#### Назначение

Пакетный вариант метода статуса. POS регулярно сверяет все открытые заказы, переданные в 1С, и узнаёт о согласовании, закрытии, пометке удаления и проведённых реализациях. Один запрос — до 200 заказов.

#### Когда вызывается и как часто

- Фоновая синхронизация статусов заказов — каждые 5 минут.
- Обычно 50–200 открытых заказов, пакетами до 200.

#### Запрос

`POST /pos/v1/orders/status`, заголовки — см. «Заголовки запроса и ответа».

| Поле | Тип | Обязательно | Описание |

## Клиенты и долг

### GET /pos/v1/customers?phone=… — поиск клиентов по телефону

#### Назначение

Найти клиентов 1С (партнёров и контрагентов) по номеру телефона. POS использует поиск в двух случаях. Первый — защита от дублей: перед созданием клиента POS проверяет, нет ли его уже в 1С. Второй — связь покупателя, который зарегистрировался в приложении, с его карточкой 1С. Привязку подтверждает администратор магазина или сам покупатель по подтверждённому телефону.

#### Когда вызывается и как часто

- При создании клиента в POS и при регистрации покупателя в приложении.
- Единицы–десятки вызовов в день.
- Если 1С не ответила или вернула ошибку, POS ищет только в своей копии справочника клиентов и не блокирует работу кассира.

#### Запрос

`GET /pos/v1/customers?phone=<номер>`, заголовки — см. «Заголовки запроса и ответа». Тела нет.

| Параметр | Где | Тип | Обязательно | Описание |
|---|---|---|---|---|
| `phone` | строка запроса | строка (телефон E.164) | да | номер в формате `+996700000001`. Символ `+` в адресе кодируется как `%2B`. POS всегда передаёт номер уже нормализованным |

#### Ответ

**200** — JSON-массив кандидатов: пустой, из одного или из нескольких элементов. Если никого не нашли, это тоже ответ 200 с пустым массивом `[]`, а не 404. Формат элемента помечен в контракте как предмет согласования (`x-status: proposed`).

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `ref` | строка (ссылка) | да | партнёр 1С |
| `contractorRef` | строка (ссылка) или `null` | да, допускается `null` | контрагент партнёра. `null`, если партнёры и контрагенты не ведутся раздельно или контрагента нет |
| `code` | строка или `null` | да, допускается `null` | код партнёра в 1С |
| `name` | строка | да | наименование клиента |
| `phone` | строка (телефон E.164) | да | найденный номер, приведённый к формату E.164 |
| `deletionMark` | логическое | да | пометка удаления. Кандидатов с пометкой POS не предлагает кассиру |

#### Ошибки

| HTTP-код | Код ошибки | Когда | Что делает POS |
|---|---|---|---|
| 400 | `POS_E_BAD_REQUEST` | нет параметра `phone` или он не в формате E.164 | ищет только в своей копии справочника |
| 401, 403 | `POS_E_UNAUTHORIZED`, `POS_E_FORBIDDEN` | доступ | ищет только в своей копии, администратору — тревога |
| 500 | `POS_E_INTERNAL` | исключение встроенного языка | ищет только в своей копии справочника |

- Верните **всех** кандидатов. Отбирать «лучшего» не нужно: выбор делает кассир или администратор.
- Повторы одного партнёра POS объединяет по `ref`, поэтому возвращать его дважды не нужно.
- Номер телефона не пишите в журнал запросов и в тексты ошибок, допустима только маска.
- Метод только читает данные.

### POST /pos/v1/customers — создать клиента

#### Назначение

Создать в 1С клиента, которого завели в POS: партнёра, контрагента (если партнёры и контрагенты ведутся раздельно) и контактную информацию «Телефон». Главное правило: новая карточка **не создаётся**, если в 1С уже есть другой клиент с тем же телефоном, — кроме случая, когда кассир сознательно подтвердил создание.

#### Когда вызывается и как часто

- Из очереди отправки, сразу после создания клиента в POS.
- Если на нового клиента сразу оформили заказ, заказ уходит в 1С только после успешного ответа этого метода.
- Ожидаемая частота — единицы–десятки в день.
- Правила создания клиента — сразу, после проверки или черновиком до подтверждения 1С, обязательные поля и кто утверждает — Q-025.

#### Запрос

`POST /pos/v1/customers`, заголовки — см. «Заголовки запроса и ответа». Ключ защиты от дублей — `externalId` в теле.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `externalId` | строка (UUID) | да | идентификатор клиента POS. Ключ защиты от дублей |
| `name` | строка | да | наименование клиента |
| `fullName` | строка или `null` | нет | полное наименование. Сейчас POS передаёт `null` — заполните типовым правилом, например по `name` |
| `phone` | строка (телефон E.164) | да | основной телефон клиента |
| `taxId` | строка или `null` | нет | ИНН, если есть |
| `kind` | строка | да | вид клиента: `individual` — физическое лицо, `entrepreneur` — индивидуальный предприниматель, `legal` — юридическое лицо. Соответствие реквизитам вашей базы (например, «Юр./физ. лицо» контрагента, типово — уточнить) — по Q-025 |
| `priceListRef` | строка (ссылка) или `null` | нет | вид цены, выбранный для клиента в POS. `null` — по умолчанию. Как отражать его в 1С — уточняется по Q-025 |
| `comment` | строка или `null` | нет | комментарий для карточки, например «Создан в POS» |
| `dedupe` | объект | да | правила проверки дублей. Состав — в следующей таблице |

Объект `dedupe`.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `byPhone` | логическое | да | искать дубли по телефону. POS всегда передаёт `true` |
| `failOnDuplicate` | логическое | да | `true` — при найденном другом клиенте с тем же телефоном отказать ответом 409. `false` — кассир с правом «создать всё равно» указал причину и подтвердил создание: создать карточку, даже если совпадение есть |

В 1С передаются **только** эти поля. Адрес, год рождения, сфера деятельности и согласия из профиля приложения в 1С не передаются. Они остаются в POS.

#### Ответ

- **201** — клиент создан.
- **200** — клиент с этим `externalId` уже создан ранее. Возвращены те же ссылки, ничего не создано.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `externalId` | строка (UUID) | да | `externalId` из запроса |
| `ref` | строка (ссылка) | да | созданный (или ранее созданный) партнёр. Без него POS считает результат неизвестным и повторит запрос |
| `contractorRef` | строка (ссылка) или `null` | да, допускается `null` | контрагент. `null`, если контрагент отдельно не создавался |
| `code` | строка или `null` | да, допускается `null` | код партнёра в 1С |
| `created` | логическое | да | `true` — создан этим запросом (201), `false` — повтор (200) |

#### Ошибки

| HTTP-код | Код ошибки | Когда | Что делает POS |
|---|---|---|---|
| 400 | `POS_E_BAD_REQUEST` | невалидный JSON, не заполнено обязательное поле | задача отправки — «ошибка», без автоповтора |
| 401, 403 | `POS_E_UNAUTHORIZED`, `POS_E_FORBIDDEN` | доступ | задача остановлена, администратору — тревога |

Клиент POS помечается «конфликт с 1С», кассиру предлагается выбрать существующую карточку, заказы перепривязываются к ней |

Элемент `details.candidates[]` при 409 содержит поля `ref` (ссылка партнёра), `name` (наименование) и `phone` (телефон E.164). Повтор того же `externalId` 409 **не** возвращает — это ответ 200.

#### Правила на стороне 1С

Порядок обработки запроса.

1. Найти `externalId` в регистре `POS_ВнешниеИдентификаторыPOS` с типом `Клиент`. Нашли — ответ 200 с `created=false` и ранее созданными ссылками. Проверку дублей в этом случае не выполнять.

- Новый партнёр и его соглашение регистрируются в плане обмена «POS» как обычно. Элемент `/changes` карточки партнёра содержит `externalId` клиента POS. Так POS сопоставит карточку, даже если ответ этого метода до него не дошёл.
- Телефон, ИНН и наименование не пишите в журнал запросов и в тексты ошибок.

### GET /pos/v1/customers/{ref}/receivables — долг клиента

#### Назначение

Вернуть снимок взаиморасчётов клиента на момент запроса: сальдо, просрочку (сумма и дни), детализацию по документам и условия соглашения — разрешена ли отсрочка, лимит, число дней отсрочки. По этим данным POS показывает кассиру долг клиента и решает, можно ли продать в долг. Сам долг POS **не вычисляет**: суммы, сроки и просрочка берутся из 1С как есть. Сальдо должно совпадать с отчётом 1С «Задолженность клиентов» на тот же момент.

#### Когда вызывается и как часто

- Фоновая синхронизация — раз в 30 минут по активным клиентам.
- По запросу кассира при открытии карточки клиента и при продаже в долг, если снимок в POS старше 60 минут.
- **Правило POS для продажи в долг.** POS продаёт в долг только по свежему снимку: не старше 60 минут от `snapshotAt`. Если снимок старше, POS пытается обновить его этим методом. Не получилось — POS **отказывает в продаже в долг** («данные о долге устарели»). Если в снимке есть просрочка (`overdueAmount` больше нуля) или превышен лимит, POS блокирует продажу в долг без обращения к 1С. Окончательный контроль долга остаётся за 1С при согласовании заказа.

#### Запрос

`GET /pos/v1/customers/{ref}/receivables`, заголовки — см. «Заголовки запроса и ответа». Тела нет.

| Параметр | Где | Тип | Обязательно | Описание |
|---|---|---|---|---|
| `ref` | путь | строка (ссылка) | да | ссылка партнёра 1С (`Ref_Key`) |

#### Ответ

**200** — снимок долга. Формат помечен в контракте как предмет согласования (`x-status: proposed`).

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `customerRef` | строка (ссылка) | да | партнёр из запроса. Должен совпадать с `ref` в пути |
| `snapshotAt` | строка (дата-время) | да | **метка времени снимка** — момент, на который рассчитаны остатки. По ней POS определяет возраст снимка |
| `balance` | строка (деньги) | да | сальдо взаиморасчётов с клиентом. Положительное — клиент должен магазину, отрицательное — переплата (аванс) |
| `overdueAmount` | строка (деньги) или `null` | да, допускается `null` | сумма просроченного долга, от 0 до сальдо. `null` — просрочка неизвестна: POS в этом случае в долг не продаёт |
| `overdueDays` | целое ≥ 0 или `null` | да, допускается `null` | число дней просрочки. Предлагаем считать по самому давнему просроченному документу (уточнить) |
| `creditAllowed` | логическое | да | соглашение с клиентом разрешает отсрочку оплаты. `false` — POS не продаёт этому клиенту в долг |
| `creditLimit` | строка (деньги) или `null` | да, допускается `null` | лимит долга. `null` — лимит не задан: POS в долг не продаёт, пока не решён вопрос Q-017 (кому разрешена продажа в долг, где задаются лимит и отсрочка) |
| `creditDays` | целое ≥ 0 или `null` | да, допускается `null` | срок отсрочки по соглашению, дней |
| `creditAvailable` | строка (деньги) или `null` | да, допускается `null` | доступный остаток лимита: лимит минус сальдо. `null`, если лимит не задан |
| `documents` | массив объектов | да | детализация долга по документам. Пустой массив, если долга нет. Состав — в следующей таблице |

Элемент `documents[]`.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `documentRef` | строка (ссылка) | да | ссылка документа расчётов. Внутри одного ответа документы не повторяются |
| `documentType` | строка | да | **вид документа** — имя типа в нотации OData, например `Document_РеализацияТоваровУслуг` |
| `number` | строка | да | номер документа, не пустой |
| `date` | строка (дата-время) | да | дата документа |
| `amount` | строка (деньги) | да | сумма документа |
| `paid` | строка (деньги) | да | оплачено по документу |
| `remaining` | строка (деньги) | да | остаток долга по документу |
| `dueDate` | строка (дата-время) или `null` | да, допускается `null` | срок оплаты. `null` — срок не задан |
| `overdueDays` | целое ≥ 0 | да | дней просрочки по документу, `0` — не просрочен |

**Вид и статус документа в POS.** Отдельных полей вида и статуса в ответе нет: POS определяет их сам.

| Вид документа (`documentType`) | Как POS показывает строку |
|---|---|
| `Document_РеализацияТоваровУслуг`, `Document_ЗаказКлиента` | начисление долга |
| `Document_ПриходныйКассовыйОрдер`, `Document_ПоступлениеБезналичныхДенежныхСредств`, `Document_ОплатаПлатежнойКартой` | оплата |
| `Document_ВозвратТоваровОтКлиента` | возврат |
| тип, в имени которого есть «Скидк» | скидка |
| прочие (корректировки долга, ввод остатков) | корректировка |

Статус строки POS вычисляет по сроку: «к оплате» — срок оплаты наступил (`dueDate` не позже даты снимка), а остаток больше нуля. Иначе — «проведён». Поэтому передавайте **только проведённые** документы. Если в вашей базе долг ведётся другими документами, сообщите их имена.

- `overdueAmount` меньше нуля или больше сальдо;
- `creditLimit` отрицательный;

- `number` пустой;

- `snapshotAt` — текущее время сервера 1С на момент расчёта, со смещением `+06:00`.
- Метод только читает данные, без кэширования.
