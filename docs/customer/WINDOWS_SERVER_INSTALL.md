# Оптомстрой POS — установка на Windows Server 2022 без Docker и Hyper-V

**Документ для администратора заказчика · версия 1.1 от 24.11.2026** (1.1 — раздел 8а «Тестовый стенд»; 1.0 от 22.11.2026 заменила проект схемы 0.2 от 21.11.2026)

**Статус.** Комплект установки для Windows Server 2022 собран и отрепетирован у нас на компьютере с Windows 11 в режиме проверки (`-DevTest`) — без прав администратора. Шаги, которым нужны права администратора (регистрация служб, учётные записи, права на папки, брандмауэр, перезапуск Apache), проверены только чтением кода и разбором скриптов. Их нужно выполнить и проверить на вашем тестовом адресе. Резервное копирование и восстановление с официальными программами PostgreSQL 17.10 тоже проверяются на тестовом адресе: в сборке PostgreSQL, которая есть у нас, нет `pg_dump` и `pg_restore`. Готовность к работе с настоящими данными мы подтвердим только после проверки на тестовом адресе.

Во всём документе соблюдаются ваши условия:

- Hyper-V не включается. Docker Desktop, WSL и Ubuntu не используются.
- Порты 80 и 443 и их привязка у Apache не меняются. Публикация 1С и SQL Server не меняются.
- В Apache добавляется только один новый виртуальный хост по имени (`api.<ваш-домен>`). Его подключает ваш администратор в согласованное окно, у подключения есть откат.
- У нашей учётной записи `posdeploy` нет прав администратора. Все шаги с правами администратора выполняет ваш администратор по командам ниже.
- Обмен с 1С — онлайн, как в утверждённом ТЗ: заказы, оплаты и возвраты сразу уходят в 1С, товары, цены, остатки и долги берутся из 1С.
- До вашего письменного разрешения на сервер ничего не устанавливается. До вашего решения о месте хранения данных на сервере во Франкфурте — только вымышленные данные.

Обозначения: **[Администратор]** — ваш администратор, PowerShell «от имени администратора»; **[posdeploy]** — наш сотрудник под учётной записью `posdeploy`; **[Держатель ключа]** — ваш сотрудник, который хранит ключ расшифровки резервных копий.

## 2. Состав служб

| Служба Windows | Что делает | Как запускается | Учётная запись | Порт |
|---|---|---|---|---|
| `OptomstroyPostgres` | База данных PostgreSQL 17.10: заказы, справочники, очередь фоновых задач | служба (`pg_ctl register`), автозапуск | `NT AUTHORITY\NetworkService` | `127.0.0.1:5433` |
| `OptomstroyApi` | HTTP API для касс, планшетов и приложений | наш хост служб `OptomstroySvc.exe`; отложенный автозапуск; зависит от `OptomstroyPostgres`; перезапуск при сбое через 10 с / 10 с / 60 с | `NT SERVICE\OptomstroyApi` (виртуальная, без пароля) | `127.0.0.1:3000` |
| `OptomstroyWorker` | Фоновые задачи: обмен с 1С, очередь отправки в 1С, SMS, фото, отметки журнала аудита | так же | `NT SERVICE\OptomstroyWorker` | нет |
| `OptomstroyBackup` | Резервное копирование: ежедневный зашифрованный дамп, архив WAL, копия фото | так же | `NT SERVICE\OptomstroyBackup` | нет |
| `migrate` (не служба) | Миграции базы | запускают скрипты установки, обновления и отката | администратор | нет |

`OptomstroySvc.exe` — наш хост служб. Он собирается из исходного кода встроенным в Windows компилятором .NET Framework 4.x; сторонних программ (WinSW, NSSM) нет. Остановка службы — штатная: хост просит процесс завершиться и ждёт 30–60 с, только потом завершает его принудительно.

Виртуальные учётные записи `NT SERVICE\…` создаёт Windows вместе со службой. Паролей у них нет, в группу администраторов они не входят. Отдельные локальные учётные записи не нужны.

**Почему свой PostgreSQL, а не ваш SQL Server.** Программа написана только под PostgreSQL (очередь задач, типы данных, расширения `pgcrypto`, `pg_trgm`, `unaccent`). Базу 1С и SQL Server мы не используем и не меняем.

## 3. Требования к CPU, RAM и диску

Только для нашей части, сверх того, что уже потребляют 1С и SQL Server.

| Компонент | RAM | vCPU | Ограничение в комплекте |
|---|---|---|---|
| PostgreSQL 17 | 1,5–2,5 ГБ (`shared_buffers` 1 ГБ, меняется параметром) | 1–2 | — |
| API | 0,5–1 ГБ | 1–1,5 | 1024 МБ, 1,5 ядра |
| Фоновые задачи | 0,5–1 ГБ | 1 | 1024 МБ, 1 ядро |
| Резервное копирование | до 0,5 ГБ | 0,5 | 512 МБ, 0,5 ядра |

**Итог: минимум 2 vCPU и 4 ГБ RAM, рекомендуется 4 vCPU и 8 ГБ RAM.** Тестовая копия системы на этом же сервере скриптами одновременно с рабочей не ставится (раздел 10): её ставим на тестовый адрес.

**Память SQL Server.** Если у SQL Server не ограничен `max server memory`, он может занять почти всю память. Скрипт установки только читает это значение и предупреждает. Проверка (только чтение):

```powershell
sqlcmd -S localhost -E -Q "SELECT name, value_in_use FROM sys.configurations WHERE name = N'max server memory (MB)'"
```

Значение 2147483647 — ограничения нет. Задать его — решение вашего администратора: настройки SQL Server мы не меняем.

**Диск** (оценка):

| Что | Том данных (`D:\Optomstroy`) | Том копий (`D:\OptomstroyBackups`, лучше отдельный) |
|---|---|---|
| PostgreSQL: данные и запас для восстановления | 20 ГБ | — |
| Фото товаров | 30 ГБ минимум / 100 ГБ рекомендуется | — |
| Журналы | 2–5 ГБ | — |
| Версии программы (2–3 версии) | ≈ 1–2 ГБ | — |
| Дампы (30 дней и ежемесячные) | — | 2–6 ГБ |
| Копия фото | — | 30 / 100 ГБ |
| Архив WAL и базовые копии | — | 10–45 ГБ |

Том не должен быть занят больше чем на 70 %. Наши данные не кладутся на том с базами SQL Server и 1С. Копии — на другом томе (если тома нет — только по вашему письменному согласию, параметр `-AllowSameVolume`). Перед обновлением нужен запас ≈ 1,2 × размер базы + 1 ГБ на томе данных. Если физический диск один, от его потери защитит только копия вне сервера (раздел 7).

**Программы.** Windows Server 2022, Windows PowerShell 5.1 (`powershell.exe`), .NET Framework 4.8 (есть в Windows Server 2022), PostgreSQL 17.10 для Windows x64 — официальные двоичные файлы (zip, папка `bin`); ставит ваш администратор. Node.js отдельно не ставится: он внутри пакета.

## 4. Внутренние порты

Наружу ничего нового не открывается. Порты 80 и 443 не меняются.

| Порт | Кто | Адрес | Доступ |
|---|---|---|---|
| 443, 80 | Apache (ваш) | как сейчас | добавляется только виртуальный хост по имени (раздел 5) |
| 3000/TCP | `OptomstroyApi` | только `127.0.0.1` | только Apache на этом сервере; плюс правило брандмауэра «блокировать входящие» `Optomstroy-Block-In-TCP-3000` |
| 5433/TCP | `OptomstroyPostgres` | только `127.0.0.1` | только локальные процессы; плюс правило `Optomstroy-Block-In-TCP-5433` |

Порт 5433 выбран, чтобы не мешать PostgreSQL на стандартном 5432, если он есть. Скрипт установки проверяет, что порты свободны, и после запуска — что слушается только `127.0.0.1`. Брандмауэр Windows не фильтрует петлевой интерфейс, поэтому Apache подключается к `127.0.0.1:3000`.

Проверка (только чтение):

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 80,443,3000,5432,5433 | Select-Object LocalAddress,LocalPort,OwningProcess
```

## 5. Схема через ваш Apache

```
Кассы / планшеты / приложения
        │  HTTPS 443, имя api.<ваш-домен> (тест: api-test.<ваш-домен>)
        ▼
Apache (ваш; Listen 80/443 без изменений)
  ├─ виртуальные хосты 1С — без изменений (стоят раньше и остаются хостом по умолчанию для *:443)
  └─ новый <VirtualHost *:443> api.<ваш-домен> (SNI, свой сертификат)
        ├─ /api/*, /health        → http://127.0.0.1:3000
        │    /health/ready — только из локальных и частных сетей, иначе 404
        ├─ /images/<sha256>/...   → файлы D:\Optomstroy\data\media\images (только GET/HEAD)
        └─ остальное              → 404
OptomstroyApi / OptomstroyWorker ── HTTPS ──► публикация 1С (на этом же сервере)
OptomstroyApi / OptomstroyWorker / OptomstroyBackup ──► OptomstroyPostgres 127.0.0.1:5433
```

**Почему отдельное имя, а не путь внутри сайта 1С.** Приложения строят адреса `/health` и `/images/...` от корня имени, а API работает под `/api/v1`. Под путём вида `https://<сайт 1С>/pos/...` проверка связи и фото в приложениях перестанут работать.

**Условие.** Новый хост безопасен для 1С, только если публикация 1С обслуживается своим именованным `<VirtualHost *:443>`, который в выводе `httpd -S` стоит раньше и является хостом по умолчанию для `*:443`. Если 1С описана в основной конфигурации `httpd.conf` без `<VirtualHost>`, через `_default_` или по IP-адресу, скрипт подключения останавливается: оформить публикацию 1С явным хостом по умолчанию — отдельное согласованное изменение у вас.

**Требования к Apache.** Apache 2.4.42 или новее, OpenSSL 1.1.1 или новее (проверено на Apache 2.4.71 Apache Lounge). Модули: `ssl`, `proxy`, `proxy_http`, `headers`, `rewrite`, `alias`, `mime`, `log_config`, `authz_core`; необязательные для сжатия — `deflate`, `filter`. Не нужны: `proxy_wstunnel`, `remoteip`, `md`.

**Сертификат.** Автоматического выпуска (как в нашем комплекте для Linux) здесь нет. Нужен сертификат для `api.<ваш-домен>` (и `api-test.<ваш-домен>`): ваш имеющийся (например, wildcard) или выпущенный вашим администратором (например, win-acme). Формат PEM с цепочкой, ключ без пароля. Продление — на вашей стороне. DNS-запись A `api.<ваш-домен>` — на IP сервера.

**Что меняется в Apache.** Скрипт `apache\enable-apache-site.ps1` (раздел 8, шаг 9):

- копирует файл хоста в `conf\extra\` и добавляет в конец `httpd.conf` одну строку `Include`;
- если обязательный модуль не загружен — раскомментирует его строку `LoadModule` (остановится, если в конфигурации есть блоки `<IfModule>` этого модуля: они начали бы действовать и для 1С);
- до изменений делает байтовую копию `httpd.conf`, проверяет сертификат и ключ, выполняет пробный запуск на свободном порту `127.0.0.1` (работающий Apache не затрагивается);
- Apache не перезапускает: перезапуск перезапускает и публикацию 1С, поэтому его делает администратор в окно.

Откат — `apache\disable-apache-site.ps1`: если `httpd.conf` после подключения не меняли — восстанавливается байт в байт; иначе удаляется только наша строка и наши `LoadModule`.

Отличия от нашего прокси для Linux: заголовок `Server` можно убрать только глобально (`ServerTokens Prod`) — это затронет и 1С, решение за вами; на неизвестные пути Apache отдаёт свою страницу 404.

## 6. Подключение к 1С на этом же сервере

Обмен — через HTTP-сервис расширения 1С «OptomstroyPOS» по контракту 1.2.0 (`ONEC_MODE=extension`), как в «Требованиях к API 1С». Туннель (WireGuard) не нужен: 1С на этом же сервере.

При установке задаются:

- `-OnecBaseUrl` — адрес публикации 1С, только `https://` (например, `https://<имя публикации 1С>/<база>`);
- `-OnecHsPath` — путь HTTP-сервиса внутри публикации, вида `hs/<имя>`;
- секреты (их вводит ваш человек при установке, ввод скрыт; или кладёт файлами в `D:\Optomstroy\secrets\` заранее): `onec_hs_user` и `onec_hs_token` (пользователь `pos_hs` и ключ `X-POS-Client-Key`) — обязательно, без них API не запускается; `onec_hs_password` — если задан в 1С; `onec_user` и `onec_password` (пользователь OData только для чтения `pos_integration`) и `onec_ca.pem` (корневой сертификат, если сертификат публикации не публичный) — файлами, если нужны.

Имя в `-OnecBaseUrl` должно совпадать с именем в сертификате публикации 1С: проверка сертификата всегда включена.

**Необязательные изменения 1С (только по отдельному согласованию, у каждого — откат):**

1. Ограничить `/hs` и `/odata` публикации 1С адресом `127.0.0.1` в Apache (`<Location "/<база>/hs"> Require ip 127.0.0.1 ::1 </Location>` и то же для `/odata`). Если публикацией пользуются извне (веб-клиент, другие интеграции) — сломает их; тогда нужна отдельная публикация для обмена с POS.
2. Записать имя публикации 1С в `C:\Windows\System32\drivers\etc\hosts` на `127.0.0.1`, чтобы обмен не выходил за пределы сервера. Это имя начнёт указывать на `127.0.0.1` для всех программ сервера; если Apache слушает 443 только на внешнем IP — обмен перестанет работать. Проверить по `httpd -S` до изменения.

**Нагрузка на 1С.** В программе есть ограничение одновременных соединений на каждого HTTP-клиента (`ONEC_MAX_CONCURRENCY=2`); ограничителя «запросов в секунду» нет. Нагрузку на 1С измерим на тестовом адресе. Если 1С недоступна, заказы и оплаты ждут в очереди и уходят позже.

## 7. Резервное копирование PostgreSQL

Копии делает служба `OptomstroyBackup` (только встроенный Node.js; сторонних программ нет).

| Что | Когда | Хранение |
|---|---|---|
| `pg_dump -Fc` рабочей базы, сразу зашифрованный | ежедневно в 05:30 по Бишкеку, после ночных заданий обмена | 30 дней; три последних не удаляются никогда |
| Ежемесячная копия (первый дамп месяца) | ежемесячно | ещё 93 дня |
| Роли (`pg_dumpall --globals-only`, без паролей) | по воскресеньям | 90 дней |
| Базовая копия `pg_basebackup` и архив WAL — восстановление на момент времени | базовая — раз в сутки; WAL закрывается не реже раза в 60 с и забирается в архив каждые 20 с | базовые копии 30 дней; WAL — пока нужен самой старой базовой копии |
| Фото и отметки журнала аудита | ежедневно | накопительная копия на томе копий (без шифрования, как в комплекте для Linux) |
| Защищённая копия файлов секретов | при установке и после изменения секретов | зашифрованный файл в `dumps\secrets` |
| Копия вне сервера | раз в сутки; архив WAL — каждые 5 мин | **не настроена до вашего выбора** (ниже) |

**Шифрование.** Дампы, базовые копии и архив WAL пишутся на диск сразу зашифрованными: на каждый файл — случайный ключ AES-256-GCM, он зашифрован открытым ключом RSA-4096; данные — кусками с проверкой подлинности каждого куска. Закрытый ключ на сервере не хранится: держатель ключа создаёт пару на своём компьютере (`backup\keygen.ps1`) и отдаёт администратору только открытую часть `backup-public.pem`. Без закрытого ключа копии не расшифровать — храните его офлайн (флешка в сейфе) и вторую копию — в другом месте.

**Копия вне сервера — нужен ваш выбор.** Варианты в комплекте: (1) общая папка (например, NAS): служба копирует туда готовые файлы, ничего не удаляя; виртуальная учётная запись службы в сети выступает учётной записью компьютера — для общей папки нужен домен или отдельная локальная учётная запись службы копий (пароль задаёт ваш администратор); (2) «забирает хранилище»: ваш NAS или другой компьютер сам забирает новые файлы с сервера (папка копий доступна ему только на чтение). Хранилище по HTTPS, S3 или SFTP без сторонних программ сейчас не поддерживается. Пока выбора нет, копии вне сервера нет: при потере сервера пропадут и копии. Скрипт состояния показывает это как проблему.

**Восстановление** (администратор вместе с держателем ключа):

```powershell
# из дампа: службы останавливаются, прежняя база переименовывается в <база>_before_<время>
D:\Optomstroy\current\backup\restore.ps1 -DumpFile D:\OptomstroyBackups\dumps\<время>.dump.optbk -KeyFile E:\key\backup-private.pem
# на момент времени: сначала во временный кластер на 127.0.0.1:5434, рабочая база не трогается
D:\Optomstroy\current\backup\restore-pitr.ps1 -KeyFile E:\key\backup-private.pem -TargetTime '2026-11-21 14:05:00+06:00' -DataDir D:\Optomstroy\data\pg-restore
D:\Optomstroy\current\backup\restore-pitr.ps1 -Apply -DataDir D:\Optomstroy\data\pg-restore   # после проверки данных
```

Порядок восстановления: остановка служб → роли → новая пустая база (та же локаль) → дамп (`pg_restore --exit-on-error`, проверка расшифровки и кода выхода) → фото → `migrate`, если программа новее копии → предупредить кассиров: заказы и корзины после момента копии потеряны, черновики не переотправлять без проверки (приложения о восстановлении сами не узнают) → запуск служб → ручной обмен с 1С и сверка очереди отправки в 1С за окно потери.

**Ежемесячная проверка.** `backup\restore-drill.ps1`: последний дамп разворачивается во временный кластер на отдельном порту, проверяются журнал миграций, ключевые таблицы и расширения, затем кластер удаляется. Рабочую базу и службы не трогает — можно при работающем магазине. Ключ приносит держатель на время проверки.

## 8а. Тестовый стенд на этом сервере (`install.ps1 -Stand`)

Тестовый стенд — та же установка, что в разделе 8, но **только с вымышленными данными**: 1С не подключается (ответы 1С — из тестовых файлов), SMS не отправляются, оплата QR — через «песочницу банка» внутри нашей программы (настоящих денег нет). На стенде мы и вы проверяем установку, службы, Apache, копии и приложения до рабочей системы. Порядок шагов — как в разделе 8; ниже — только то, что для стенда отличается. До вашего письменного разрешения на сервере ничего не ставится.

**Что сделать до установки [Администратор]:**

1. **Порт 22 для `posdeploy`.** Мы проверяем стенд только чтением, под `posdeploy` по SSH. Сейчас (23–24.11.2026) порт 22 с нашего адреса не отвечает. Нужно: служба OpenSSH Server запущена; вход `posdeploy` по ключу; порт 22 открыт **только для нашего IP** (адрес и открытый ключ пришлём отдельным письмом). Проверка и настройка:

   ```powershell
   Get-WindowsCapability -Online -Name OpenSSH.Server*        # State: Installed — сервер SSH установлен
   # если не установлен:
   Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
   Set-Service sshd -StartupType Automatic; Start-Service sshd
   Get-Service sshd                                           # Status: Running
   # вход только с нашего адреса (вместо <наш IP> — адрес из письма):
   New-NetFirewallRule -Name OptomstroyPosdeploySsh -DisplayName "Optomstroy posdeploy SSH" -Direction Inbound `
       -Protocol TCP -LocalPort 22 -RemoteAddress <наш IP> -Action Allow
   ```

   Открытый ключ положите в `C:\Users\posdeploy\.ssh\authorized_keys` (доступ к файлу — только `posdeploy`, SYSTEM и Administrators). Если у провайдера VPS есть свой сетевой фильтр (панель управления сервером), порт 22 для нашего адреса нужно открыть и там. Широкое правило Windows «OpenSSH-Server-In-TCP» (порт 22 для всех адресов), если оно создалось при установке, лучше выключить: `Disable-NetFirewallRule -Name OpenSSH-Server-In-TCP`.

2. **Имя стенда.** Выберите один вариант:
   - **А (рекомендуем):** `api-test.optomstroy.kg` — DNS-запись A `api-test.optomstroy.kg` → `37.114.51.144` в зоне вашего домена `optomstroy.kg`;
   - **Б (временно, без DNS):** `api-test.37.114.51.144.sslip.io` — публичный сервис sslip.io сам отвечает на это имя адресом `37.114.51.144`, записей заводить не нужно.

   Приложения для стенда мы собрали на имя Б. Если выберете А — сообщите, мы пересоберём приложения на новое имя.

3. **Сертификат для имени стенда.** Сейчас ваш Apache на 443 отдаёт сертификат `1c.optomstroy.kg` — для имени стенда приложения его не примут. Нужен сертификат именно для выбранного имени (PEM с цепочкой и ключ без пароля), удобнее всего — бесплатный Let's Encrypt через win-acme. Если сертификат для `1c.optomstroy.kg` вы уже получаете каким-то способом — используйте тот же способ.

   Let's Encrypt проверяет имя запросом `http://<имя стенда>/.well-known/acme-challenge/...` на порт 80, поэтому Apache на порту 80 должен отдавать для этого имени файлы проверки из папки, в которую пишет win-acme. **Осторожно:** если в выводе `httpd -S` на порту 80 нет ни одного `<VirtualHost>` (порт 80 обслуживает основная конфигурация), то первый добавленный `<VirtualHost *:80>` станет хостом по умолчанию для всего порта 80 — это затронет сайты на порту 80. В этом случае пришлите нам вывод `httpd -S`, решим вместе. Для варианта А можно обойтись без порта 80: проверка через DNS (запись TXT в зоне `optomstroy.kg`) — так тоже умеет win-acme.

   Пример для проверки через порт 80 (имена параметров — по документации win-acme вашей версии; папки — любые ваши):

   ```powershell
   # 1) папка для файлов проверки и строки в Apache (в окно для перезапуска Apache; только для имени стенда):
   #    <VirtualHost *:80>
   #        ServerName api-test.37.114.51.144.sslip.io
   #        DocumentRoot "C:/Apache24/acme/api-test"
   #        <Directory "C:/Apache24/acme/api-test">
   #            Require all granted
   #        </Directory>
   #    </VirtualHost>
   # 2) выпуск сертификата в PEM-файлы:
   wacs.exe --source manual --host api-test.37.114.51.144.sslip.io --validation filesystem `
       --webroot C:\Apache24\acme\api-test --store pemfiles --pemfilespath C:\Apache24\conf\ssl --installation none
   ```

   win-acme кладёт в `C:\Apache24\conf\ssl` файл цепочки и файл ключа (точные имена файлов зависят от версии — посмотрите в папке). Их пути укажите при установке в `-CertFile` (файл **с цепочкой**) и `-KeyFile`. Либо переименуйте их в имена по умолчанию: `C:\Apache24\conf\ssl\<имя стенда>.fullchain.crt` и `C:\Apache24\conf\ssl\<имя стенда>.key`. Продление win-acme делает сам (задание Планировщика), но Apache читает сертификат только при запуске — после продления (примерно раз в 60 дней) нужен перезапуск Apache в окно. Ключ — только для учётной записи службы Apache и администраторов.

### 8а.1. Стенд с настоящей 1С через ОС_API шлюза (только чтение)

По умолчанию стенд берёт ответы 1С из тестовых файлов. Его можно переключить на HTTP-сервис **ОС_API**, который уже работает на этом сервере для шлюза (расширение 1С шлюза, публикация `uk_main_fr`, адрес `http://localhost/uk_main_fr/hs/os/api/v1`). Тогда стенд показывает **настоящий каталог, цены и остатки** из этой базы 1С.

Что важно знать:

- **В 1С ничего не пишется.** Стенд только читает: проверку связи, каталог, цены, остатки и фото товаров. Заказы, покупатели и оплаты в 1С не создаются (это отдельное решение, позже).
- **Пароль 1С никому не пересылается и нигде не показывается.** Стенд входит в 1С под тем же пользователем, что и шлюз (`ONEC_API_USER` / `ONEC_API_PASSWORD` в переменных среды Windows на этом сервере). Скрипт сам переносит их в папку секретов стенда и ничего не печатает на экран и в журнал.
- Адрес 1С — только на этом же сервере (`http://localhost/...`); наружу публикация 1С не открывается.
- Стенд должен быть уже установлен (раздел 8а выше).

> **Когда можно включать.** Только после двух условий: (1) владелец магазина и специалист 1С письменно ответили на наш вопрос Q-388 — база `uk_main_fr` **тестовая** (в ней нет настоящих данных покупателей, а чтение со стенда не нагружает рабочую 1С); (2) после этого мы письменно сказали «да» на включение. До этого стенд остаётся на тестовых файлах (`ONEC_MODE=fixtures`), и команды ниже не запускаются. Если `uk_main_fr` окажется рабочей базой, стенд к ней не подключается — нужна тестовая копия базы с ОС_API.

**Две команды [Администратор]** — PowerShell «от имени администратора», под той учётной записью, под которой настроен шлюз (или любой, если `ONEC_API_USER` / `ONEC_API_PASSWORD` заданы как системные переменные):

```powershell
# 1) учётные данные шлюза → D:\Optomstroy\secrets\onec_user и onec_password (значения не выводятся):
D:\Optomstroy\current\scripts\import-onec-credentials.ps1
# ожидается «готово»; доступ к файлам — только администраторы, SYSTEM и службы OptomstroyApi / OptomstroyWorker (чтение)

# 2) включить ОС_API: та же команда установки стенда, что в разделе 8а, плюс -StandOnecOsApi <адрес публикации 1С>:
cd C:\Users\<admin>\setup\pkg\scripts
.\install.ps1 -Stand -StandOnecOsApi http://localhost/uk_main_fr -Zip <путь к zip> -Sha256 <SHA256 из письма> `
    -PgBin 'C:\Program Files\PostgreSQL\17\bin' -ApacheDir C:\Apache24 -ApacheServiceName <служба Apache> `
    -ApacheServiceAccount <учётная запись службы Apache>
# установка запишет ONEC_MODE=os_api в D:\Optomstroy\config\api.env и worker.env и сама перезапустит службы
```

Адрес — корень публикации, **без** `/hs/...` в конце (путь сервиса `hs/os/api/v1` установка добавит сама).

Если скрипт 1) пишет:

- «не найдены в переменных среды» — у шлюза не заданы `ONEC_API_USER` / `ONEC_API_PASSWORD` в этом пользователе. Запустите скрипт под учётной записью шлюза, либо положите два файла сами: `D:\Optomstroy\secrets\onec_user` (имя пользователя 1С) и `D:\Optomstroy\secrets\onec_password` (пароль) — по одной строке, в Блокноте кодировка «UTF-8» (не «UTF-8 с BOM»); затем команда 2) — она сама выдаст службам право чтения этих файлов;
- «заданы по-разному в нескольких местах» — выберите нужное место: `import-onec-credentials.ps1 -Source HKLM` (или `-Source HKCU`, или имя учётной записи из сообщения);
- «уже есть и отличается» — пароль у шлюза сменили: замените файлы `import-onec-credentials.ps1 -Force`, затем снова команда 2).

**Повторный запуск** установки стенда (например, при новых тестовых номерах) режим ОС_API **не выключает** — установка помнит адрес в `D:\Optomstroy\config\install.json`. **Вернуть тестовые файлы вместо 1С:** команда 2) с `-StandOnecOsApi fixtures`.

Необязательные настройки (в `D:\Optomstroy\config\api.env` и `worker.env`, затем перезапуск служб — `install.ps1` ещё раз или `Restart-Service OptomstroyApi, OptomstroyWorker`): `ONEC_OSAPI_PRICE_TYPES` — какие виды цен брать (UUID через запятую; пусто — все не удалённые), `ONEC_OSAPI_WAREHOUSES` — остатки каких складов (UUID; пусто — все), `ONEC_OSAPI_POLL_SECONDS` — как часто перечитывать каталог, цены и остатки (секунды, кратно 60, от 60 до 3600; по умолчанию 300).

**Проверка:** `D:\Optomstroy\current\scripts\status.ps1` — код 0; в приложении (вход тестовым номером) — каталог, цены и остатки из 1С. Если что-то не так — пришлите журналы `D:\Optomstroy\logs\install-<время>.log` и `import-onec-credentials-<время>.log` (паролей в них нет).

## 9. Обновление и откат

**Миграции базы применяются только вперёд.** Если новая версия изменила схему базы, откатить программу можно только вместе с базой.

**[posdeploy]** загружает пакет в `D:\Optomstroy\incoming\`. **[Администратор]**:

```powershell
D:\Optomstroy\current\scripts\update.ps1 -Zip D:\Optomstroy\incoming\Optomstroy-Server-<версия>-win-x64.zip -Sha256 <SHA256 из письма>
```

Порядок: сверка пакета и всех файлов (службы работают) → план по журналу миграций (в базе миграции, которых нет в новой версии, — стоп) → остановка API и фоновых задач (служба копий продолжает архив WAL) → зашифрованный дамп перед обновлением (нет дампа — обновление прекращается, прежняя версия запускается) → если меняется схема — копия базы внутри PostgreSQL → новые несекретные настройки дописываются в `.env` → переключение на новую версию, миграции, запуск, проверки.

Сбой — **автоматический откат**: прежняя версия и настройки возвращаются, база — из копии; изменённая база сохраняется как `<база>_failed_<время>`. Если новая версия успела поработать, созданные ею заказы есть только в этой базе — перед её удалением сверьте с 1С. Код выхода: 0 — обновлено, 1 — не обновлено. Обновление целиком у нас заняло 58 с на пустой базе (API недоступен часть этого времени); на ваших данных — дольше.

Ручной откат:

```powershell
D:\Optomstroy\current\scripts\rollback.ps1                    # на версию до последнего обновления
D:\Optomstroy\current\scripts\rollback.ps1 -RestoreSnapshot   # вместе с базой (если update.ps1 запускали с -KeepSnapshot)
```

Если база новее прежней версии, откат только программы отклоняется: варианты — `-RestoreSnapshot` или восстановление из дампа перед обновлением (раздел 7).

**Стенд с 1С через ОС_API (раздел 8а.1).** Версии, выпущенные до этого режима, не знают `ONEC_MODE=os_api` — с ним их API и фоновые задачи не запускаются. Поэтому `rollback.ps1` отклоняет откат на такую версию, пока в `D:\Optomstroy\config\api.env` или `worker.env` стоит `os_api` (службы при этом не останавливаются). Сначала верните стенд на тестовые файлы — команда 2) раздела 8а.1 с `-StandOnecOsApi fixtures` (или вручную `ONEC_MODE=fixtures` в обоих файлах), затем `rollback.ps1`.

**Новый секрет в версии** (будет в примечаниях к выпуску): до `update.ps1` администратор кладёт файл в `secrets\`, дописывает строку `ИМЯ_FILE=D:\Optomstroy\secrets\<файл>` в нужный `.env` и выдаёт службе чтение файла.

## 10. Удаление (полный откат установки) [Администратор]

Из распакованного пакета (не из `D:\Optomstroy\current\scripts`):

```powershell
.\uninstall.ps1                       # программа и службы удаляются, данные и копии остаются
.\uninstall.ps1 -KeepData:$false      # и данные (база, фото, секреты, настройки) — после ввода подтверждения
```

Порядок: наш хост в Apache отключается (если был подключён; Apache перезапускает администратор в окно) → службы останавливаются и удаляются → PostgreSQL останавливается, служба снимается → правила брандмауэра удаляются → программа удаляется, только если всё прошло без ошибок. Папка копий не удаляется никогда. Apache (кроме нашего хоста), 1С и SQL Server не затрагиваются. Если ваш администратор менял `max server memory` ради нашей части — вернуть прежнее значение по его решению.

**Ограничения.** Рабочий и тестовый контуры на одном сервере этими скриптами одновременно не ставятся (имена служб фиксированы). В тестовом контуре запрос кода на номер не из `-TestPhones` на 1 минуту закрывает вход по SMS для всех, в том числе для тестовых номеров.

## 11. Что могут `posdeploy` и администратор

| Действие | posdeploy | Администратор |
|---|---|---|
| Загрузить пакет в `incoming\` | да | да |
| Читать журналы `logs\` | да | да |
| Состояние `status.ps1` (службы, версии, готовность, копии, диск; `-Json` — для мониторинга) | да | да |
| Запуск, остановка, опрос `OptomstroyApi` и `OptomstroyWorker` | да | да |
| Опрос состояния `OptomstroyPostgres`, `OptomstroyBackup` (для `status.ps1`) | да, только опрос | да |
| Запуск и остановка `OptomstroyPostgres`, `OptomstroyBackup` | нет | да |
| Установка, обновление, откат, удаление; секреты, настройки, данные; Apache, брандмауэр, PostgreSQL | нет | да |

Кто может менять файлы программы или настройки, тот может запустить свой код от имени служб и прочитать секреты. Поэтому `posdeploy` прав записи туда не получает.

## 12. Что нужно от вас

Ответить можно коротко, номер и вариант:

1. **Подтверждение варианта.** Рабочая система на вашем сервере как службы Windows рядом с 1С, SQL Server и Apache: А — да, после проверки на тестовом адресе (рекомендуем); Б — только тест, рабочая система — на отдельном Linux-сервере. Пока ответа нет — на сервер ставим только тестовый контур с вымышленными данными и только по вашему письменному разрешению.
2. **Имена и сертификат.** Имена `api.<ваш-домен>` и `api-test.<ваш-домен>`, DNS-записи A; сертификат: А — ваш имеющийся (рекомендуем), Б — выпустит ваш администратор (win-acme); окно для перезапуска Apache и кто проверяет 1С после него. Пока ответа нет — хост в Apache не подключаем.
3. **Сведения об Apache:** версия, путь, имя службы, учётная запись службы, вывод `httpd -n <служба> -v`, `-M`, `-S`; используются ли глобально `mod_remoteip`, `Header`, `ServerTokens`.
4. **Диски:** на каких томах базы SQL Server и 1С; можно ли выделить отдельные тома под наши данные и под копии.
5. **Память:** сколько занимают 1С и SQL Server; задан ли `max server memory`.
6. **1С:** адрес публикации и путь HTTP-сервиса (`hs/<имя>`); установлено ли расширение «OptomstroyPOS» по контракту 1.2.0; какой сертификат у публикации; кто пользуется публикацией из интернета; согласны ли на необязательные изменения раздела 6.
7. **Копия вне сервера:** где (NAS, другой компьютер) и какой вариант раздела 7; кто держатель ключа копий.
8. **Место данных:** письменное решение о хранении настоящих данных на сервере во Франкфурте (до него — только вымышленные данные).
9. **Окна:** для установки, перезапуска Apache, обновлений и плановой перезагрузки Windows — согласованные с работой 1С.
10. **Письменное разрешение** на установку на тестовом адресе с датой.
11. **Для тестового стенда (раздел 8а):** порт 22 для `posdeploy` с нашего адреса; имя стенда — А `api-test.optomstroy.kg` (рекомендуем) или Б `api-test.37.114.51.144.sslip.io`; кто выпускает и продлевает сертификат для этого имени.

## 13. Открытые вопросы и ограничения

- Шаги администратора (службы под SCM, права NTFS, брандмауэр, права `posdeploy`, ваш Apache) у нас не выполнялись — проверяются на тестовом адресе (раздел 8, шаги 5–9).
- Дамп, базовая копия, восстановление и восстановление на момент времени с официальными программами PostgreSQL 17.10, а также копия базы при обновлении с новой миграцией — проверяются на тестовом адресе.
- Копия вне сервера не настроена до вашего выбора (раздел 7).
- Защищённая копия секретов хранится вместе с зашифрованными дампами (наши общие требования предусматривают отдельное хранение) — это принимается вместе с ответом на вопрос 1 раздела 12.
- Ограничителя частоты запросов к 1С в программе нет; нагрузку на 1С измерим на тестовом адресе.
- Время восстановления на Windows не назначено — появится после учений на тестовом адресе.
