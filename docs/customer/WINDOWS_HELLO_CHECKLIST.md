| Связанные документы | Инструкция к веб-демо, раздел «Вход по лицу или отпечатку» — это другая проверка (вход в браузере на Windows) |

**Зачем.** Вы выбрали для Windows «Лицо без PIN (Рекоменд.)» (ответ 2026-11-08). В приложении это сделано: кнопка «Войти через Windows Hello» открывает рабочий экран без PIN приложения. Автоматические проверки проходят, но настоящий Windows Hello (камера, ключ в защищённом модуле компьютера) можно проверить только на компьютере с камерой Windows Hello. Пока эта проверка не пройдена, на рабочем сервере вход через Windows Hello без PIN выключен.

## 1. Что нужно

- Компьютер с Windows 10 или 11 и **камерой с поддержкой Windows Hello** (инфракрасной). Обычная веб-камера лицо для Windows Hello не распознаёт. Без такой камеры Windows предложит отпечаток или PIN Windows, а вход именно по лицу проверить нельзя.
- **Личная учётная запись Windows** — в неё входите только вы (почему — раздел 4).
- От нас: архив приложения для Windows, настроенный на **тестовый сервер**, и сам тестовый сервер, где вход без PIN разрешён по правилу раздела 4. Рабочий сервер и настоящие данные не нужны.
- **Два номера телефона:** ваш и второй — только для пункта 3.9 (например, другого сотрудника; без второго номера пропустите 3.9). Мы заранее вносим оба номера на тестовый сервер. SMS тестовый сервер не отправляет: код входа мы сообщим вам перед проверкой.
- **Время, согласованное с нами.** В пунктах 3.8 и 3.9 мы меняем настройку тестового сервера, это 1–2 минуты. На время проверки наш человек должен быть на связи: напишите или позвоните ему перед пунктом 3.8.
- Около 45 минут. Из них 31 минута — ожидание блокировки по простою (пункт 3.4).

**Как запустить приложение.** Распакуйте архив в любую папку и запустите `optomstroy.exe`. Сборка не подписана, поэтому Windows может показать «Система Windows защитила ваш компьютер»: «Подробнее» → «Выполнить в любом случае» `[ТИПОВО]`. Вверху будет полоса тестовой сборки — так и должно быть. Если Windows пишет, что не хватает файла `.dll`, напишите нам.

## 2. Настроить Windows Hello (лицо)

1. «Пуск» → «Параметры» → «Учётные записи» → «Варианты входа».
2. «ПИН-код (Windows Hello)» → «Настроить», если PIN Windows ещё не задан. Без него лицо не включается.
3. «Распознавание лиц (Windows Hello)» → «Настроить» → посмотрите в камеру. Если носите очки, потом нажмите «Улучшить распознавание».
4. Проверка самой Windows: нажмите Win+L и посмотрите в камеру. Windows должна открыться без PIN.

Если пункт «Распознавание лиц» пишет, что недоступен, — камеры Windows Hello нет. Проверку можно пройти отпечатком или PIN Windows, но не лицом: напишите нам. Названия пунктов в Windows 10 и 11 немного различаются `[ТИПОВО]`.

## 3. Проверки

В колонке «Итог» запишите «да», «нет» или «не проверено» и дату. Каждое «нет» опишите одной фразой; снимок экрана — по желанию.

**3.1. Самопроверка Windows.** «Пуск» → наберите «Windows PowerShell» → откройте (права администратора не нужны; PowerShell 7 не подходит). Вставьте весь блок и нажмите Enter. Окно Windows Hello при этом не открывается.

```powershell
Add-Type -AssemblyName System.Runtime.WindowsRuntime
$asTask = [System.WindowsRuntimeSystemExtensions].GetMethods() | Where-Object { $_.Name -eq 'AsTask' -and $_.GetParameters().Count -eq 1 -and $_.GetParameters()[0].ParameterType.Name -eq 'IAsyncOperation`1' } | Select-Object -First 1
function Wait-WinRt($op, [Type]$type) { $t = $asTask.MakeGenericMethod($type).Invoke($null, @($op)); $t.Wait(-1) | Out-Null; $t.Result }
$ucv = [Windows.Security.Credentials.UI.UserConsentVerifier, Windows.Security.Credentials.UI, ContentType = WindowsRuntime]
$kcm = [Windows.Security.Credentials.KeyCredentialManager, Windows.Security.Credentials, ContentType = WindowsRuntime]
'Hello: ' + (Wait-WinRt ($ucv::CheckAvailabilityAsync()) ([Windows.Security.Credentials.UI.UserConsentVerifierAvailability]))
'Keys: ' + (Wait-WinRt ($kcm::IsSupportedAsync()) ([bool]))
```

Ожидается: `Hello: Available` и `Keys: True`. Другие ответы `[ТИПОВО]`: `NotConfiguredForUser` — Windows Hello не настроен (раздел 2); `DeviceNotPresent` — нет устройства Windows Hello; `DisabledByPolicy` — запрещено настройками компьютера. `Keys: False` — вход без PIN на этом ПК невозможен, будет только «Windows Hello перед вводом PIN».

## 4. Почему вход без PIN — только на личной учётной записи Windows

- **Windows Hello узнаёт владельца учётной записи Windows, а не сотрудника.** Приложение получает от Windows только «подтверждено». Лицом, отпечатком или PIN Windows — и чьим — Windows приложению не сообщает.
- **Общий кассовый ПК с одной учётной записью** («Касса» на всех) поэтому сотрудников не различает. PIN Windows у такой учётной записи знают все кассиры. Отпечатки разных людей можно добавить в одну учётную запись `[ТИПОВО]`. Вход без PIN приложения открыл бы рабочее место сотрудника, чей ключ сохранён, любому, кто знает PIN Windows. Продажи, оплаты, возвраты и долги записались бы на чужое имя.
- **Правило «один человек на учётной записи».** Вход без PIN приложения работает только там, где за последние 30 дней входил один человек. Для приложения одна установка — это одна учётная запись Windows на этом ПК: данные приложения лежат в папке учётной записи. Как только на той же установке по SMS входит второй сотрудник, вход без PIN у прежних выключается, а второй включить его не может (пункт 3.9).
- **На общей кассе** остаётся «Windows Hello перед вводом PIN»: лицо, затем PIN приложения. Каждый кассир вводит свой PIN, и приложение знает, кто работает.
- **Если кассиру нужен вход без PIN** — у него должна быть своя учётная запись Windows на этом ПК со своим лицом. Смена кассира — смена пользователя Windows (Win+L → другой пользователь) `[ВЫВОД]`. Это ваше решение; отдельно не проверялось.
- Срок 30 дней — наше предложение, его нужно подтвердить. Вход без PIN для всех, без этого правила, — только по вашему письменному решению.
