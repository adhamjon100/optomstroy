## Часть А. ИТ магазина

### А1. Какой планшет подходит `[ТИПОВО — проверить на модели]`

- Android 9 или новее; экран 10–11″; работа в горизонтальной ориентации.
- Ширина экрана не меньше 600 lp. На маленьком экране режим планшета не включается: подключение отклоняется с подсказкой (P-002 §8.8).
- Без Google-аккаунта и без других учётных записей. Планшет используется только под это приложение: магазина приложений и других программ после подготовки на нём не будет.
- Wi-Fi в торговом зале (обязательство O-31), питание у места установки.
- Модель, число, место и склад планшетов пока не названы: `[ТРЕБУЕТ РЕШЕНИЯ ЗАКАЗЧИКА: Q-342]`.

### А2. Проверка одного планшета до покупки остальных (Q-342)

Сначала покупается **один** планшет выбранной модели. Стандартными средствами Android проверяем, что модель принимает «владельца устройства» (Device Owner) и режим закрепления `lock task`. Остальные планшеты лучше покупать после пилота (P-002 §7 п. 2, риск RR-T4).

Что нужно: компьютер с Android SDK Platform-Tools (программа `adb`), USB-кабель, сам планшет.

1. Сбросьте планшет к заводским настройкам (разрешение заказчика — обязательство O-30).
2. Первичную настройку пройдите **без** Google-аккаунта и без учётной записи производителя («Пропустить»). Иначе Android не назначит владельца устройства.
3. Откройте «Настройки» → «О планшете». Нажмите 7 раз «Номер сборки» — появятся «Параметры разработчика». В них включите «Отладка по USB».
4. Подключите планшет к компьютеру и подтвердите на планшете доступ компьютера. Команда `adb devices` должна показать планшет.
5. Назначьте владельца устройства. Есть два варианта.
   - **Есть сборка нашего приложения с закреплением** (после задачи TAB-2-09):
     ```
     adb install <файл приложения>.apk
     adb shell dpm set-device-owner com.example.optomstroy/.KioskDeviceAdminReceiver
     ```
   - **Сборки ещё нет** `[ТИПОВО — проверить по описанию Test DPC]`. Используется тестовое приложение Google «Test DPC» из официального источника Google (проект Android Enterprise samples):
     ```
     adb install <файл Test DPC>.apk
     adb shell dpm set-device-owner com.afwsamples.testdpc/.DeviceAdminReceiver
     ```
     Затем в Test DPC включите режим закрепления (`lock task`) для любого приложения.
6. Ожидаемый ответ команды: строка `Success: Device owner set to package …` `[ТИПОВО]`. Частые отказы:
   - `… there are already some accounts on the device` — на планшете есть учётная запись. Удалите её или повторите с шага 1.
   - `… there are already several users on the device` — на планшете несколько пользователей (гостевой, рабочий профиль, «Защищённая папка» и т. п.). Удалите их или повторите с шага 1.
7. Проверьте состояние:
   ```
   adb shell dumpsys device_policy
   ```
   В выводе должен быть владелец устройства с указанным выше компонентом `[ТИПОВО: вид вывода зависит от версии Android]`.
8. Проверьте закрепление в работе. При включённом `lock task` кнопки «Домой» и «Недавние», шторка уведомлений и долгое нажатие питания не выводят из приложения.
9. Запишите результат в опись (А4) и сообщите нам: модель, версия Android, номер сборки, результат («принимает» / «не принимает» и текст ошибки).
10. После проверки тестовым приложением снова сбросьте планшет к заводским настройкам: Test DPC удаляется только сбросом `[ТИПОВО]`. Если проверка шла с нашим приложением, планшет можно сразу готовить по А3.

Если модель не принимает владельца устройства — новую модель не покупайте и сообщите нам. Тогда варианты такие: исправление в коде или закрепление экрана с PIN устройства (Р-11 (б)). Без закрепления планшет в зал не ставится.

### А3. Подготовка планшета (каждый планшет)

1. Сброс к заводским настройкам и первичная настройка без учётных записей — как А2, шаги 1–2.
2. Подключите Wi-Fi торгового зала. Включите автоматические дату и время, часовой пояс — Бишкек.
3. Включите отладку по USB (А2, шаг 3) и установите приложение. Канал установки — тот же, что для других Android-устройств магазина (Q-008, Q-193). Сборка — подписанная тем же ключом, что все следующие обновления (Q-349, см. А5).
4. Назначьте приложение владельцем устройства:
   ```
   adb shell dpm set-device-owner com.example.optomstroy/.KioskDeviceAdminReceiver
   ```
5. Передайте планшет администратору для подключения (Б1). При подключении приложение само включает закрепление и ограничения (P-002 §8.10):
   - нет шторки и уведомлений;
   - нет безопасного режима и сброса из настроек;
   - нет отладки по USB и установки приложений;
   - нет службы автозаполнения;
   - приложение назначено экраном «Домой».

   После этого `adb` перестаёт работать — так и должно быть.
6. Установите планшет на место, подключите к питанию. Наклейка с именем планшета допустима. **Аварийный код на планшет не клеить.**
7. Заполните строку описи (А4).

### А5. Обновление приложения на планшете (вместе с администратором, 5–10 минут на планшет)

Планшет нельзя доводить до состояния «нужно обновить». Минимальную версию приложения для Android не поднимают, пока хоть один планшет на старой версии. Версию каждого планшета видно в «Планшетах магазина». Планшеты ведутся в журнале установок регламента обновления (16 §10.8, шаги 3–4).

1. Администратор стоит у планшета. На своём телефоне он открывает «Планшеты магазина» → планшет → «Отключить планшет» и подтверждает PIN.
2. На планшете появляется «Планшет отключён администратором». Закрепление и ограничения снимаются, данные планшета удаляются, открывается экран входа.
3. ИТ включает отладку по USB (А2, шаг 3) и ставит новую версию **поверх** установленной:
   ```
   adb install -r <файл приложения>.apk
   ```
   - Приложение не удалять.
   - Новая версия должна быть подписана **тем же ключом**, что установленная. С другим ключом установка не пройдёт, а владелец устройства не сохранится `[ТИПОВО]`.
   - Сейчас сборки подписываются отладочным ключом. Постоянный ключ подписи — вопрос `[ТРЕБУЕТ РЕШЕНИЯ ЗАКАЗЧИКА: Q-349]`.
4. Администратор входит на планшете своим номером, кодом из SMS и PIN. Затем: «Планшеты магазина» → «Подключить заново этот планшет». Появляется **новый** аварийный код: он — в новый конверт (Б2).
5. Запишите установку в журнал установок и в опись.

Если планшет уже показывает «Планшет нужно обновить. Обратитесь к продавцу»:

1. Аварийный выход по коду из конверта (Б4).
2. Затем шаги 3–5.

### А6. Подготовка заново

Когда нужна: аварийный код потерян, а планшет без связи, с истёкшим подключением или просит обновления (P-002 §8.9 п. 2).

1. Сброс к заводским настройкам из меню восстановления. Комбинация кнопок зависит от модели `[ТИПОВО — проверить на модели]`.
2. Подготовка по А3.
3. Администратор подключает **ту же** запись планшета: «Подключить заново этот планшет», выбор из списка. История заявок планшета сохраняется.

Если планшет на связи, сброс не нужен. Администратор отключает планшет удалённо и подключает заново — с новым кодом (Б2).

### А7. Сеть магазина

- Планшеты работают только через Wi-Fi магазина.
- На сервере можно включить проверку «только из сети магазина» (`KIOSK_ALLOWED_CIDRS`). Тогда сообщите разработчику внешние адреса сети магазина.
- Планшет вне этих адресов показывает «Планшет не в сети магазина. Обратитесь к продавцу». Если проверка выключена, адреса не нужны.

## Часть Б. Администратор

### Б1. Первое подключение планшета

1. Войдите на подготовленном планшете (А3) своим номером, кодом из SMS и PIN.
2. «Планшеты магазина» → «Сделать это устройство планшетом магазина».
3. Укажите имя (например, «Планшет у входа») и склад. Подтвердите PIN.
4. Появится «Аварийный код выхода: … Он показывается один раз». Перепишите 8 цифр на бумагу и уберите в конверт (Б2).
5. Планшет откроет каталог. Ваши данные на этом устройстве удаляются, закрепление включается.
6. Проверьте в «Планшетах магазина» на своём телефоне: у планшета **не** должно быть пометки «Закрепление не включено». Если она есть, владелец устройства не назначен — позовите ИТ (А3, шаг 4).

### Б2. Конверты с аварийными кодами

- **Один конверт — один планшет.** На конверте — имя планшета и дата. Конверт запечатан и хранится в сейфе магазина (или код — в вашем менеджере паролей).
- **Не фотографировать** на общий телефон. Не клеить на планшет.
- **Новый код при каждом подключении.** Код выдаётся при первом подключении, при каждом подключении заново и после обновления. Новый код отменяет прежний. Старый конверт уничтожьте.
- **Хранители.** Кто хранит конверты и кто подключает планшеты заново, назначает заказчик до пилота (обязательство O-32): `[ТРЕБУЕТ РЕШЕНИЯ ЗАКАЗЧИКА]`.
- **Журнал конвертов:**

| Планшет | Дата кода | Причина (подключение / заново / обновление) | Кто запечатал | Где хранится | Старый конверт уничтожен |
|---|---|---|---|---|---|
| | | | | | |

- **Конверт потерян, планшет на связи.** «Отключить планшет», затем «Подключить заново этот планшет» — новый код. Если планшет без связи — А6.

### Б3. Подключение заново раз в 180 дней (2–3 минуты)

Подключение планшета действует 180 дней (решение Р-22 (а)). Если планшет 7 дней подряд не выходил на связь, подключение заканчивается раньше. В «Планшетах магазина» видно «Подключение действует до …». За 30 дней приложение напоминает.

**Плановое подключение заново** (подключение ещё действует):

1. Встаньте у планшета. На своём телефоне: «Планшеты магазина» → «Отключить планшет» → PIN.
2. На планшете войдите своим номером, кодом и PIN.
3. «Подключить заново этот планшет» → новый аварийный код → новый конверт.

**Подключение уже закончилось.** Планшет показывает «Планшет нужно подключить заново. Обратитесь к продавцу». Витрины нет, закрепление остаётся.

1. Аварийный выход по коду из конверта (Б4).
2. Затем вход и «Подключить заново этот планшет».

### Б4. Аварийный выход на месте

Нужен, когда у планшета нет связи, он просит обновления или подключение закончилось.

1. Нажмите и держите логотип 5 секунд. Откроются экранные кнопки.
2. Введите 8 цифр аварийного кода → «Выйти из режима планшета».
3. Неверный код: «Неверный код. Осталось попыток: …». После 5 неверных — пауза 15 минут, и после перезапуска тоже.
4. **Выход со связью.** Код проверяет сервер, сессия планшета сразу закрывается.
5. **Выход без связи.** Код проверяет сам планшет. На экране будет «Выход выполнен без связи. Отключите этот планшет в списке «Планшеты магазина»». Сделайте это сразу со своего телефона: «Отключить планшет». Затем, когда планшет снова нужен, — «Подключить заново этот планшет» (новый код).

### Б5. Отключение планшета

Когда: кража, ремонт, планшет больше не нужен.

1. «Планшеты магазина» → планшет → «Отключить планшет» → PIN. Можно с любого своего устройства.
2. Действует сразу: планшет показывает «Планшет отключён администратором» и снимает закрепление.
3. При краже: отключите сразу, сообщите владельцу. Порядок действий — в регламенте 16 «украден или потерян планшет». Персональных данных покупателей на планшете нет.

### Б6. Что видно в «Планшетах магазина» и какие приходят сигналы

**В списке:** имя, склад, статус, последняя связь, закрепление, версия приложения, срок подключения.

**Сигналы администратору** (без телефонов и адресов):

- много запросов кода с одного планшета за 10 минут;
- исчерпан суточный лимит кодов планшета;
- планшет вне сети магазина (если проверка сети включена, А7);
- до конца подключения меньше 30 дней;
- версия планшета ниже рекомендуемой;
- планшет не на связи дольше 15 минут в часы работы магазина.

Часов работы пока нет: `[ТРЕБУЕТ РЕШЕНИЯ ЗАКАЗЧИКА: Q-341]`. По ответу владельца «Пока заглушки (Рекоменд.)» пояснение такое: «Часы работы — пустая настройка: пока она не задана, сигнал выключен.»

### Б7. Общие настройки планшетов

Настройки задаются в разделе настроек приложения (SCR-46) и действуют на все планшеты сразу:

| Настройка | Значение |
|---|---|
| Автосброс | 2 минуты без касаний |
| Предупреждение «Вы ещё здесь?» | 15 секунд |
| Номер заявки на экране | 60 секунд |
| Лимит кодов на планшет | 30 в час, 200 в сутки |
| Часы работы магазина для сигнала «не на связи» | пусто — сигнал выключен |

Значения уточняются на пилоте.

## Часть В. Кассир и старший продавец

### В1. Как приходит заявка

- **Уведомление.** «Новая заявка с планшета № …» приходит в течение минуты.
- **На кассе.** Заявка видна в блоке «Ожидают оплаты» с пометкой «С планшета».
- **Поиск.** Покупатель называет номер заявки, например POS-2026-000123. Найдите её по номеру.
- **Цена.** На планшете покупатель видел обычные цены магазина. Если заявка на карточку клиента с договором, сервер уже поставил договорную цену. Сумма на кассе бывает меньше, чем на планшете. Надпись на планшете — «Договорные цены применит кассир».

### В2. «Клиент найден по номеру: …»

Подсказка: «Спросите имя покупателя и сверьте с карточкой до оплаты».

1. Спросите покупателя, как его зовут. Имя из карточки вслух не называйте.
2. **Имя совпало** — примите оплату как обычно: наличными или по QR (сменой способа оплаты).
3. **Имя не совпало** — номер в 1С мог устареть. По этой заявке оплату не принимайте:
   1. «Повторить заказ» → клиент «Розничный покупатель» или верная карточка.
   2. Оплата нового заказа.
   3. Отмена заявки с планшета (подтверждение PIN, В4).

### В3. «Клиент не определён — выберите карточку» или «Новый покупатель»

Подсказка: «Повторить заказ на карточку клиента».

- **Обычная покупка.** Заявка оформлена на «Розничного покупателя» по обычной цене. Примите оплату как обычно.
- **Особые случаи:**
  - у покупателя договор с магазином (договорная цена);
  - нужен долг (перевести заявку с планшета в долг нельзя — решение Р-06 (а));
  - покупка от организации: сначала проверьте документы (ИНН, доверенность).

  Что делать в особом случае:

  1. «Повторить заказ» → выберите карточку клиента.
  2. Оформите заказ.
  3. Отмените заявку с планшета (В4).

### В4. Отмена заявки с планшета

- Для кассира это отмена чужого заказа, поэтому её подтверждают PIN.
- На самом планшете отменить заявку нельзя.
- Товары отменённой заявки в корзину планшета не возвращаются.

### В5. Неоплаченные заявки (решение Р-18 (а))

- **Резерва нет.** Заявка с планшета товар не резервирует.
- **В конце рабочего дня** кассир отменяет неоплаченные заявки этого дня с планшета (с PIN).
- **Утром** старший продавец открывает список заказов с фильтром «С планшета» и отменяет оставшиеся. Вчерашние заявки в «Ожидают оплаты» уже не видны.
- **Номер покупателя** в заявке скрывается через 90 дней в любом случае.

### В6. Помощь покупателю у планшета

- **Код из SMS** покупатель вводит сам. Не просите назвать вам код: в SMS написано «Никому не сообщайте».
- **Сообщения на планшете:**
  - «Нет связи», «Планшет не в сети магазина», «Сервис временно недоступен»;
  - «Не удаётся отправить код. Обратитесь к продавцу», «Заявку не удалось отправить. Обратитесь к продавцу».

  В этих случаях оформите заказ покупателю в своём приложении, как сейчас. Если на планшете проблема со связью или подключением, сообщите администратору.
- **«Товара стало меньше»** — покупатель исправляет количество в корзине. Заявку можно отправить тем же кодом в течение минуты после ввода кода. Позже нужен новый код.
