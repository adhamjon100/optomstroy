# Экран выбора товаров (SCR-10/11/12) по макету заказчика 2026-10-28 — отчёт

Дата: 2026-10-28. Ветка: `develop/stages-b-g`, база — коммит `8fea341`. **Ничего не закоммичено.**

**Дополнение 2026-10-29 — перенос утверждённого прототипа во Flutter с паритетом функций: §12.** Палитра, шапка, навигация, каталог и корзина перенесены из `docs/specification/visual/prototype/Main.dc.html` (ADR-111, ADR-112). Пункты 4, 5, 6, 8 и 11 §10 и пп. 2, 4, 5 §9 закрыты переносом. На 2026-10-29 работа тоже не закоммичена: коммит делает главная сессия.

Вход: макет заказчика 2026-10-28 (экран «Сантехника») и задание заказчика:
- сохранить фирменный стиль;
- убрать мигание всего экрана при смене категории, найдя первопричину, а не скрыв её анимацией;
- сделать выбор товара быстрым: это POS для продавца, а не витрина;
- все тексты — по-русски, данные — только настоящие;
- не сломать корзину, сканер, авторизацию и роли.

Вопросы и временные решения по ходу работы — `docs/stages/CAT_UI_spec_questions.md` (CQ-STAB-01…04, CQ-LAY-01…12, CQ-REV-01…05). Решение — ADR-110 (`docs/specification/15_DECISION_LOG.md`, приложение К).

## 1. Итог

- **Мигание устранено по существу, а не спрятано.** Все четыре причины найдены и сняты (§3).
- На medium, expanded и large каталог, категория и поиск — одна страница:
  - анимации перехода нет;
  - шапка, колонка категорий, панель управления и корзина (CP) не пересоздаются;
  - скелетона при данных в кэше нет;
  - фото не проявляются заново;
  - на одну смену категории уходит ровно один запрос.
- На compact поведение прежнее: `push` с переходом платформы, «Назад» работает.
- Экран перестроен по макету: колонка плиток корневых категорий, лента подкатегорий с картинками, панель «Сначала новые · Избранное · Недавние | Сетка · Список · Компакт · сортировка · Фильтры», поиск по центру шапки.
- Сохранено: фирменная палитра B (заливка #FF8700 с текстом #1B1F2A, цены #B04E00), формат цены проекта, рабочие элементы шапки продавца.
- Данные только с сервера и из кэша: 28 карточек на 5 экранах сверены с API, расхождений 0.
- Новых ключей ARB нет: все подписи — существующие ключи 02 §7.
- Не менялись: бизнес-правила, API, контракты, ядро, `resursi/`, роли и корзина.
- ТЗ синхронизировано (§5):
  - 02 — версия 1.15;
  - 03 — версия 1.6;
  - `visual/navigation.md` — версия 1.11;
  - 15 — версия 1.15, ADR-110.

## 3. Первопричины мигания — доказательство «до/после»

**Как замеряли.** Тест `catalog_stability_test.dart` строит настоящие маршруты приложения (`$appRoutes`, `StatefulShellRoute`). Платформа — Windows (переход Material по умолчанию — Zoom), окно expanded 1366×900, данные в локальном кэше. Сценарий: `/catalog` → категория «А» → категория «Б», после каждого нажатия — 40 кадров по 16 мс. Считаются кадры анимации страницы, кадры с обёрткой Zoom, кадры скелетона, запросы списка и пересоздание частей экрана (идентичность Element/State).

**Как получили «до».** Тот же тест (только замер, без проверок) выполнен на копии `HEAD` (`git archive HEAD` → `D:/optomstroy/.tmp/head_src`, файл `zz_before_probe_test.dart`). Журнал — `D:/optomstroy/.tmp/head_src/before_probe.txt`.

**Как получили «после».** Текущая рабочая копия, журнал — `D:/optomstroy/.tmp/cat_sync/test_catalog_cart.txt`.

## 4. Что изменено на экране

Подробно — 02 SCR-10, SCR-11, SCR-12, блоки «Изменения … по макету заказчика 2026-10-28».

1. **Шапка.** Поиск по центру. «Бургер», часы, дата и `SyncIndicator` сохранены как рабочие элементы продавца. Имя и роль — из сессии.
2. **Колонка категорий (expanded/large).**
   - Ширина 120 lp, свёрнутая — 72 lp.
   - Плитки корневых категорий настоящего дерева (11 корней на стенде).
   - Изображение категории, иначе иконка по `iconKey` или по смыслу названия; фото товара не подставляется.
   - Выбранная плитка — корень текущего пути (заливка `primaryContainer`, обводка и текст `primaryText`).
   - Заголовок колонки — «Каталог», под категориями — «★ Избранное».
3. **Лента подкатегорий (medium+).**
   - Плитки 128×120: «Все» и непустые подкатегории.
   - У листовой подкатегории показываются её соседи, текущая выбрана.
   - Прокрутка жестом, тачпадом, мышью и колесом, стрелки ‹ ›.
4. **Панель управления.**
   - «Сначала новые» (сортировка `updatedAt:desc`), «Избранное», «Недавние» (с «Очистить»).
   - Сетка · Список · Компакт, сортировка, «Фильтры».
   - Подписи — если помещаются; при прокрутке панель закрепляется сверху.
5. **Сетка.** Формула 03 §7.3: 1366 lp с CP — 4 колонки, без CP — 6, 1100 — 3. «Компакт» — узкий набор колонок, «Наименованию» ≥ 220 lp.
6. **Быстрый выбор.**
   - Колонка, лента и строка поиска не сбрасываются при смене категории.
   - Фокус поиска и `F2` сохраняются, сканер HID работает.
   - Блокировка 300 мс — только для `push`, быстрый выбор категорий подряд выполняется.
   - Повторные нажатия «+ Добавить» во время добавления поглощаются (без дублей).
7. **Фото.** Относительный адрес `/images/{sha}/{size}` разрешается от адреса API. До исправления фото с сервера не показывались совсем.

## 9. Отличия от макета (осознанные)

1. Цена «8 450 сом» без «,00»: это формат проекта, 03 §9.16 и Q-108 (CQ-LAY-10).
2. У продавца при 1366 lp с корзиной 4 колонки, а не 6: CP продавца всегда видна, карточка ≥ 160 lp. Без корзины (клиент) — 6 (CQ-REV-01).
3. В шапке есть «бургер», часы, дата и статус синхронизации — рабочие элементы продавца (CQ-LAY-08).
4. Вместо «Новые» — «Сначала новые»: в API нет признака «новинка», это сортировка (CQ-LAY-04).
5. При 1366 lp с корзиной панель управления занимает две строки.
6. В данных стенда две корневые категории «Смесители», одна с 1 товаром. Это данные фикстур, не ошибка приложения.

**2026-10-29 (перенос прототипа, §12).** Пп. 2 и 5 больше не действуют: постоянной CP нет, у продавца при 1366 lp — 6 колонок, подписи вида видны с 1280 lp. П. 3 уточнён: «бургер» теперь открывает drawer навигации, часы, дата и `SyncIndicator` сохранены. П. 4: подпись «Новые» принята из прототипа, смысл прежний — сортировка (Q-335).
