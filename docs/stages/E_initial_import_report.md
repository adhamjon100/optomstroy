Пояснения к таблице:
- **products.** Вставлено 6 879 = 4 951 живой товар + 1 878 упаковок + 50 товаров с пометкой удаления в 1С. Помеченные

- **prices.** Вставлено 26 584 = 26 579 цен + 5 видов цен. `$count` сверяется только по справочной части

  подсчётами (§2.2).
- **stock.** `$count` не сверяется по той же причине, что и цены.

**Объяснённая разница — служебные варианты.** В `product_variants` строк больше, чем характеристик в 1С. У каждого
товара есть служебный вариант `is_default` без `onec_ref` (07 §5.17, DATA-116; RM-E-001 п. 4: товар без
характеристик имеет ровно один такой вариант). На этот вариант ложатся:
- цены без характеристики;
- остатки без характеристики;
- штрихкоды без характеристики.

Для 1С это не объект, поэтому ожидаемое число — число живых товаров. Сверка `$count` (`CountCheckService`, 05
SYNC-068) служебные варианты не считает: в `local_total` входят только строки с `onec_ref`.

Сверка `$count` заданием `sync.count_check`:
- categories, products (2 таблицы), variants, units, barcodes, warehouses, prices — `success`;
- **расхождений 0**.

## 3. Что это подтверждает и чего нет

**Подтверждено на фикстурах:**
1. Полная загрузка всех сущностей каталога. Количество в источнике = количество в БД по каждой таблице, разница
   объяснена (п. 1 критерия).
2. 0 ошибок маппинга (п. 2 критерия).
3. Отчёт озаглавлен «на фикстурах, не реальная интеграция» (п. 3 критерия, SRC-D-176).

Повторяемость:
- конвейер тот же, что в pos-worker;
- `node scripts/local-stack.mjs catalog-smoke` повторяет загрузку отдельным процессом и проверяет API на настоящих
  процессах (22/22 PASS);
- `serve --catalog-fixtures[=N]` даёт такой же каталог для Flutter.

**Не подтверждено (нужна тестовая копия 1С):**
- фактические имена объектов и полей 1С: allow-list и маппинг — `[ТИПОВО]` (Q-010);
- объёмы и время загрузки на данных заказчика;
- нагрузка на сервер 1С (18 §7.4);
- фото через HS `/pos/v1/images` и выгрузка CommerceML заказчика.

Повтор RM-E-011 на копии — после приёмки API: `docs/stages/E_onec_extension_acceptance.md` §2, §4.

**Связывание вида цены по умолчанию** (найдено при интеграции, EQ-INT-03). Seed создаёт вид цены «Розничная» без
`onec_ref`. Раньше полная загрузка создавала рядом второй вид цены «Розничная» из 1С. Вид цены по умолчанию
оставался без цен, и цены в каталоге не видел никто.

Сейчас конвейер связывает строку seed с видом цены 1С того же имени:
- `onec_ref` записывается в строку seed;
- `is_default`, `visible_to_roles` и ссылки сохраняются.

Тест: `test/sync-apply/catalog-apply.spec.ts`. В этом прогоне seed не применялся, потому что БД содержит только
миграции. Связывание проверено в `catalog-smoke`, где выполняются migrate и seed.
