# RM-B-001 — Утверждение ТЗ

**Дата:** 2026-10-21
**Текст сообщения заказчика:** «ТЗ УТВЕРЖДЕНО. НАЧИНАЙ РАЗРАБОТКУ»
**Ворота G-B1:** закрыты (ядро R0 §22.13 п. 5: точная фраза — единственное условие).

## Ответы заказчика, полученные вместе с утверждением (2026-10-21)

Заказчик ответил на часть вопросов непосредственно перед утверждением. Ответы внесены в ядро решений как §24 (v1.9) и в документы ТЗ (задача RM-B-002):

| Вопрос | Ответ заказчика | Решение |
|---|---|---|
| Q-006 — палитра и логотип | «оранжевый» | основная палитра — вариант B «Оранжевый» (03 §5.3), логотип оранжевый (ядро §24.1) |
| Q-001 — кто регистрируется | «в регистрации — клиент, а продавца добавляет супер-админ» | регистрация по телефону — для клиентов, режим клиента в R1; сотрудников создаёт администратор приглашением (ядро §24.2) |
| Q-010 / Q-011 — 1С | «по 1С ничего нет и не знаю; [специалист 1С] сказал, что по запросу выдаст нам API» | основной путь — API специалиста 1С по документу `18_ONEC_API_REQUEST.md`; OData — запасной (ядро §24.3) |
| Q-014 — QR-оплата | «не совсем ясно; в 1С есть API-интеграция» | основной вариант — QR через 1С (`QR_PROVIDER=onec`), запасной — ручное подтверждение кассиром (ядро §24.4) |

## Блокирующие вопросы без ответа

По остальным блокирующим вопросам (14 §2) форма ответа не поступила. Действуют рекомендуемые допущения 14; они блокируют только зависящие от них задачи этапа 2 (13 §9). Ворота G-B2 закрываются «на жёлтый» с записью последствий в отчёте этапа B (RM-B-013).
