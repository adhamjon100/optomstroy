# Словарь строк UI (ARB): заметки RM-B-007

Это задача RM-B-007 этапа B «контракты» (13_IMPLEMENTATION_ROADMAP §3.2). Файлы `app_*.arb` собирает скрипт. Руками их не правят: правка идёт в ТЗ, затем сборка запускается заново.

| Файл | Назначение |
|---|---|
| `app_ru.arb` | Шаблон (`template-arb-file`, 03 §16.1). Значения, `@key.description`, `@key.placeholders` (ICU, типы) |
| `app_ky.arb`, `app_en.arb` | Каркас: те же ключи и плейсхолдеры; значение — копия `ru`; в `description` — пометка «TODO перевод» (D-38, Q-007) |
| `../../scripts/build_arb.py` | Сборка из markdown-таблиц ТЗ |
| `../../scripts/check_arb_keys.py` | Проверка (критерии RM-B-007) |

Копия в `pos-app/lib/l10n/` и `flutter gen-l10n` относятся к RM-C-002.

## 1. Запуск

```
python -I -X utf8 scripts/build_arb.py            # пересобрать ARB
python -I -X utf8 scripts/build_arb.py --check    # код 1, если файлы на диске отличаются от сборки
python -I -X utf8 scripts/build_arb.py --report   # полный журнал решений
python -I -X utf8 scripts/check_arb_keys.py       # проверки RM-B-007; код 1 при ошибке
python -I -X utf8 scripts/check_arb_keys.py --self-test         # самопроверка ICU-парсера
python -I -X utf8 scripts/check_arb_keys.py --strict-coverage   # нехватка общих ключей 03 — ошибка
```

Сборка детерминирована: ключи отсортированы, меток времени нет, перевод строки LF, UTF-8 без BOM. Сетевых запросов нет.

## 2. Источники и порядок приоритета

Порядок: ядро R0 v1.9, затем 03 §16, затем 02 §7. Основание — ядро §19.1: «при конфликте имени ключа приоритет у 03».

1. **02 §7, «Сводный словарь строк UI».** Таблица «Ключ ARB | Русский текст | Экран | Примечание», 1893 строки. Владелец экранных строк. Из ячеек «Экран» и «Примечание» собирается `description` в виде «Экран: … . <примечание>. Источник: 02 §7».
2. **03 §16, правила и общие ключи.** Скрипт берёт:
   - пары `` `ключ` «текст» `` из §16.2 и §16.5;
   - коды `` `CODE` («текст» `` из §16.5, ключ `error_` + код в нижнем регистре по правилу §16.2: `QR_UNAVAILABLE`, `RETURN_QTY_EXCEEDED`);
   - таблицу плюрализации §16.3;
   - ключи `auth_error_*` из §13.3: на этот раздел ссылается §16.5.
   В 03 найдено 74 ключа с текстом. Из них 44 совпали с 02, 3 расходятся (п. 3.1), 27 новых.
3. **Ядро §6 / §17.3.** Отсюда берётся перечень `sync_entity`, по нему сверяется развёртка шаблона (п. 3.3).

## 3. Решения при сборке

### 3.1. Конфликты текстов 02 ↔ 03

| Ключ | 02 §7 | 03 | Решение |
|---|---|---|---|
| `error_qr_unavailable` | «QR временно недоступен» | §16.5: «Банк недоступен» | **Оставлен текст 02** (`KERNEL_OVERRIDES`, B-AR-11 архитектурной проверки этапа B). По ядру v1.9 §24.4 в R1 основной вариант `QR_PROVIDER=onec` — QR формирует 1С, «Банк недоступен» для него неверно; нейтральный текст 02 подходит и для `onec`, и для `bakai` (R2). 03 §16.5 нужно выровнять |
| `payment_review_no_webhook` | «Требует проверки: нет уведомления банка» | §16.5 и §9.39: «Ожидает подтверждения по выписке» | Взят текст 03 (приоритет 03; ядро §23 п.4) |
| `ds_onec_down` | «…продажа в долг — только по актуальным данным о долге» | §16.5: «…продажа в долг недоступна» | **Оставлен текст 02** (исключение `KERNEL_OVERRIDES` в `build_arb.py`; второе — `error_qr_unavailable`). По ядру §22.4 при недоступности 1С продажа в долг разрешена по свежему полному снимку. Текст 03 противоречит ядру, а 02 (SCR-90, ссылка на ядро §22.4) с ним выровнен. 03 §16.5 нужно выровнять |

В `description` каждого такого ключа записан и отклонённый текст.

### 3.2. Нормализация текстов 02 §7

- **Служебные примечания в ячейке текста перенесены в `description`.** Это скобки, внутри которых есть код:
  - `customers_search_placeholder` — «(общий `ds_search_placeholder_customers`)»;
  - `payment_qr_auto_note` — «(показ — только при `Payment.qr.autoConfirm=true`)».
- **Запись «{count} товар / товара / товаров» (три формы) преобразована в ICU plural.** Схема: `one`/`few`/`many`, а `other` берёт форму `few`, как во всех строках 03 §16.3. Преобразовано 7 ключей:
  - `catalog_found_count` — результат дословно совпал с 03 §16.3;
  - `category_found_count`, `favorites_products_found`, `filters_show_n`, `reports_orders_count`, `sync_errors_count`, `variant_sheet_count`.
- **Звёздочка обязательного поля сохранена как текст макета:** `reg_field_name` «ФИО *» и подобные.
- **Ячейки с одним текстом для нескольких ключей** (`link_contact_shop`, `pending_contact_shop`) в 02 §7 уже разнесены по отдельным ключам. Каждый берётся как есть.

### 3.3. Ключи-шаблоны 02 §7 (4 строки)

| Шаблон | Решение |

| `audit_action_<action>` | Не развёрнут. Тексты в 02 §7 не заданы («≈ 70, словарь 11 §7.2»). 14 конкретных `audit_action_*` из 02 §7 включены |
| `audit_group_<name>` | Не развёрнут. Есть 11 подписей, но коды групп в ТЗ не определены |
| `role_<code>_summary` | Не развёрнут. Текстов нет («Краткое описание прав роли», 11 §4.4) |

### 3.4. Плейсхолдеры

- Типы назначаются по преамбуле 02 §7:
  - `int` — `{count}`, `{n}`, `{seconds}`, `{minutes}`, а также любая переменная `plural` (например `{days}` в `receivables_overdue`);
  - `String` — все остальные (значения уже отформатированы: деньги, даты, телефоны, `{qty}`, `{percent}`, `{limit}` и т. д.).
- Поле `example` не заполняется. ТЗ не задаёт примеров для каждого ключа, а придумывать их запрещено. Ориентиры для переводчика — в `description`.
- Плейсхолдеры извлекаются тем же ICU-парсером, которым пользуется `check_arb_keys.py`.

### 3.5. Дополнения 03 §16.3

- **`unit_pcs_full`.** В 03 заданы только формы `one{штука} few{штуки} many{штук}`. ICU требует варианта `other`, поэтому сборка добавила `other{штуки}` (= `few`, по образцу таблицы §16.3) и обернула формы в `{count, plural, …}`.
- **Новые ключи вне префиксов экранов 02.** Это `unit_pcs`, `unit_pcs_full`, `otp_attempts_left`, `receivable_overdue_days`, `variants_count`, `cart_items_count`, `customer_orders_count`, `notifications_unread`. Проверка допускает их как ключи таблицы 03 §16.3.

### 3.6. Каркас `ky`/`en`: отступление от 03 §16.6

03 §16.6 говорит, что `ky` и `en` создаются «без строк (fallback `ru`)». По постановке RM-B-007 (D-38 допускает каркас) они создаются с полным набором ключей:

- значение — копия `ru`;
- `description` начинается с «TODO перевод: …»;
- плейсхолдеры те же.

Последствия для этапа C (RM-C-002, SCR-42):

- Правило «язык показывается при заполненности ≥ 95 %» нельзя считать по наличию ключа. Непереведённой строкой считается та, у которой `description` начинается с «TODO перевод».
- Плюральные строки `ky` содержат категории `few`/`many` из `ru`. Для `ky` (`one`/`other` по CLDR) лишние категории игнорируются; при переводе их удаляют.

### 3.7. Служебный атрибут

Во всех трёх файлах есть `"@@x-generated-by"`. gen-l10n не считает ключи с префиксом `@` сообщениями. Это нужно подтвердить на `flutter gen-l10n` в RM-C-002; если атрибут помешает, его уберут из `GENERATED_BY`.

## 4. Пробелы ТЗ: ключи без текста не создавались

`check_arb_keys.py` выводит покрытие как информацию; с `--strict-coverage` это становится ошибкой. Тексты должен дать владелец 03 §16.5 (ядро §18.1).

**Состояние на 2026-10-21 после правок B-AR-11:** `--strict-coverage` → `итог: ошибок 2` (22 `status_*` и 22 `error_*`
без текста). Включить `--strict-coverage` в CI (`contracts-lint`, RM-C-011) можно только после того, как владелец 03
даст тексты (срок по B-AR-11 — до RM-C-002); до этого в CI запускается режим без флага, а покрытие видно в логе.
Тексты в этом каталоге не придумываются (правило «не выдумывать значения»): часть смыслов есть в колонке «Что делает
клиент» 08 §2.4 («Сессия завершена», «Неверный код, осталось N попыток» …), но владелец ARB-текстов — 03.

Прочие замечания к текстам (значения взяты как есть, с TODO для владельца 02):

- **Формы plural не заданы.** В примечании есть пометка «ICU plural», но в тексте одна форма, поэтому оставлен простой плейсхолдер:
  `audit_filters_button`, `cart_clear_dialog_body`, `checkout_items_count`, `favorites_tab_customers_count`, `favorites_tab_products_count`, `home_my_orders_active`, `parked_delete_dialog_body`, `scan_choose_variant`, `scan_series_summary`, `sync_interval`, `variant_selected_summary`, `ds_button_show_n` (03: «(плюрал)»).
- **Неполный набор форм.** Записи не преобразованы в ICU, чтобы не придумывать недостающие формы:
  - `search_hint_more_chars` — «символ / символа»;
  - `variant_added_snackbar` — «позиции / позиций»;
  - `notifications_new_above` — «новое / новых уведомления(-й)»;
  - `catalog_card_variant_label` — два варианта строки через « / »; вероятно, нужен `{count, plural, =0{…} other{…}}`.
- **Значение — ссылка на шаблон, а не текст:**
  - `register_consent_pd_text` — «Шаблон 1 (11 §10.3)»;
  - `register_security_consent_text` — «Шаблон 3 (11 §10.3)».
  Полный текст и версия ждут ответа на Q-027.
- **Ключ из 02 §7 с пометкой «с v1.4 не используется».** Это, например, `admin_settings_customer_mode_*_confirm` и `audit_export_r2_tooltip`. Такие ключи сохранены, потому что 02 §7 их сохраняет. Проверка «нет неиспользуемых ключей» (T-DS-080) выполняется на этапе C по коду.
