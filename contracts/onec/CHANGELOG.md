Формат — по [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/); версия — `info.version` контракта (правило
ONEC-033, 05 §6: добавление полей и уточнение описаний — минорная версия в пределах `v1`; удаление, переименование и

(поле `version`, сейчас 1): его изменение — отдельная запись вида «odata-allowlist <N>». Подробный журнал версий и
статусы согласования со специалистом 1С — `contracts/onec/NOTES.md` §6.

## [1.2.0] — 2026-11-04 — заявка с планшета магазина (P-002, ADR-115)

Минорное изменение: `info.version` 1.1.0 → 1.2.0, только описания. Основание — P-002 «Планшет магазина» редакции 5,
утверждённый владельцем 2026-11-04 («P-002 утверждаю, делай»); решение — ADR-115; владелец содержания — 05 v1.7 §6.8
(ONEC-109, ONEC-110), изложение для специалиста 1С — ТЗ для программиста 1С 1.2, раздел Г.9, вопросы 88–92. Набор
операций, схемы тел, шаблон `x-comment-pattern` и фикстуры не менялись (`scripts/check_onec_paths.py` — 0 ошибок).

### Уточнено

- `OrderCreateRequest.comment`: `x-comment-format` дополнен вариантом заявки с планшета магазина —
  `POS <externalId> · <publicNumber>[ · заявка клиента| · Заявка с планшета «<имя>»][ · <комментарий>]`; описание поля —
  пример `POS <uuid> · POS-2026-000123 · Заявка с планшета «Планшет у входа»` (05 §6.8 п. (1), (6); Q-344, вопрос 89).
  Шаблон `x-comment-pattern` этот вариант уже принимал.
- `OrderCreateRequest.createdByUserCode`: у заявки с планшета — UUID технического пользователя планшета, один на планшет,
  не меняется при подключении заново (05 ONEC-109; Q-343, вопрос 88). Формат поля не меняется.
