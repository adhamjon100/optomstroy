# onec-extension — расширение 1С «OptomstroyPOS»

Каталог создан задачей **RM-C-001**. Владелец — роль `ONEC` (13 §5.2, `docs/repo_layout.md` §4).

## Назначение

Здесь хранятся материалы по расширению конфигурации 1С «OptomstroyPOS». Расширение даёт POS-системе API на стороне 1С:

- HTTP-сервис `/pos/v1/*`;
- план обмена «POS»;
- методы QR-оплаты через 1С (05 §6.7, `QR_PROVIDER=onec`).

**Код расширения пишет специалист 1С заказчика**, а не команда POS (ядро R0 §24.3, задача RM-B-014). Он работает на тестовой копии базы 1С по документу [`docs/specification/18_ONEC_API_REQUEST.md`](../docs/specification/18_ONEC_API_REQUEST.md), этапы 18 §7.1: подготовка, чтение, запись, QR.

Роль `ONEC` в этой задаче:

- отвечает на вопросы специалиста;
- сверяет промежуточные версии с контрактом;
- ведёт журнал версий.

## Источники истины

| Что | Где |
|---|---|
| Требования к методам, ошибкам, повторам | `docs/specification/05_ONEC_INTEGRATION.md` §6 (владелец содержания, ONEC-074) |
| Изложение для специалиста 1С | `docs/specification/18_ONEC_API_REQUEST.md` (только после 05 §6) |
| Машинно-проверяемый контракт | `contracts/onec/onec-http-service.v1.yaml`, `contracts/onec/odata-allowlist.yaml`, `contracts/onec/fixtures/` (RM-B-004) |
| Журнал версий расширения | `docs/integration/onec_extension_versions.md` (RM-B-014; создаёт `ONEC` при получении первой версии) |

Контракт меняется только по процедуре 13 §5.3: сначала 05 §6, затем 18, затем `contracts/onec/`. Если реализация расходится с контрактом, это исправляет специалист 1С.

## Что сюда кладётся

- Копии выгрузок версий расширения (`*.cfe`), полученные от специалиста 1С. Имя файла: `OptomstroyPOS_<версия>_<YYYY-MM-DD>.cfe`. Это двоичный файл, см. `.gitattributes`.
- Короткие заметки о каждой версии. Подробный журнал ведётся в `docs/integration/`.

## Что сюда не кладётся

- Адрес публикации HTTP-сервиса, логины и пароли интеграции. Они передаются **только через секрет-хранилище заказчика**, не через чат и не через git (RM-B-014; CONTRIBUTING.md §1 п. 7; 16 §4.3).
- Выгрузки базы 1С (`*.dt`, `*.1CD`) и персональные данные.

## Состояние

На 2026-10-21 версий расширения нет. Срок, тестовая копия и сопровождение не определены (Q-011 закрыт частично, B-KI-08). Пока API нет, `pos-api` работает с 1С в режиме фикстур (`ONEC_MODE=fixtures`, RM-C-008). Запасной путь — решение 13 §3.12: фаза 0, `QR_PROVIDER=none`.
